# [기술 보고서] 고성능 데이터 지향 경제 시뮬레이션 백엔드 아키텍처
**High-Performance Data-Oriented Economic Simulation Backend Architecture**

본 문서는 유니티 기술 스택(DOTS, Burst Compiler, Job System)을 활용하여 2,500개 노드와 7,500개 지능형 에이전트 규모의 실시간 계층형 경제 시뮬레이션을 구현하기 위한 기술 백엔드 아키텍처 명세 및 보고서입니다. 다른 개발자 및 아키텍트와의 기술 검토(Technical Review) 및 회의 진행을 위해 가독성 중심으로 작성되었습니다.

---

## 1. 아키텍처 핵심 요약 (Executive Summary)

*   **시뮬레이션 스케일:** 2,500개 가변 노드 군집 + 7,500개 독립 지능 에이전트.
*   **핵심 도전 과제:** 매 턴 대규모 차익 예측, 공간 탐색, 5단계 트리 상향식 집계, 실시간 세대교체 연산을 유니티 메인 스레드 지연(GC 오버헤드) 없이 처리.
*   **기술 스택 선정이유:** 전통적인 객체지향(OOP) 클래스 기반 설계는 메모리 파편화(Pointer Chasing)와 가비지 컬렉션(GC)으로 인해 기하급수적인 성능 저하를 유발합니다. 따라서 메모리를 구조체 형식으로 일렬 배치하는 **데이터 지향 설계(DOD)**와 LLVM 기반 고속 기계어 변환을 지원하는 **유니티 Burst 컴파일러**를 채택했습니다.

---

## 2. 데이터 구조 및 메모리 레이아웃 (Memory Layout)

모든 데이터는 가비지 컬렉터를 자극하지 않는 **무참조 구조체(Value-Type Struct)**로 설계되었으며, 네이티브 힙 영역에 연속 배열(`NativeArray`) 구조로 강제 정렬됩니다.

### A. 에이전트 지능 및 성향 9개 조합 분류
*   **1차 성격 (Personality):** 신중한(Cautious), 공격적인(Aggressive), 평범한(Normal)
*   **2차 직업 (Occupation):** 지역 상인(Local), 원정 상인(Expedition), 행상인(Peddler)
*   **구현 특성:** 다형성(`interface` / `virtual`)을 배제하고 구조체 내부에 고정 계수 플래그(`IntelligenceProfile`)를 패킹하여 CPU의 분기 예측 실패율을 0%에 수렴시킵니다.

### B. 격자 공간 분할 및 정보 불균형 구조
*   **고정 크기 기억 가방:** 에이전트 내부에 최대 4개의 노드 정보를 캐싱하는 구조체(`ObservedNodeMemory`) 내장.
*   **정보 수집 및 전파:** `NativeParallelMultiHashMap`을 이용해 5타일 반경(약 3개 노드 상주) 정보를 매 턴 갱신하며, 동일 좌표에 중첩된 에이전트 간의 로컬 메모리를 가비지 없이 고속 전사(복사)하여 시장의 '정보 불균형(소문)'을 유도합니다.
*   **미지 영역의 거시 참조:** 로컬 가방에 없는 미지의 원거리 노드를 판단할 때는 52턴 주기로 발행되는 공식 거시 회계 보고서의 군집 평균 수치에 의존하도록 유도합니다.

## 3. 실시간 가변 계층형 트리 집계 (Dynamic Tree Aggregation)

게임 플레이 도중 무역망 재편, 동맹 변경, 영토 확장 등으로 인해 노드의 상위 집합 관계가 실시간으로 바뀔 때의 연산 파이프라인입니다.

*   **인덱스 기반 포인터 기법:** 포인터 객체 참조 대신 역방향 인덱스 ID(`ParentClusterID`) 테이블을 구현합니다. 노드를 이동시킬 때 리스트에서 제거/추가하는 메모리 재할당 오버헤드가 없으며, 단 하나의 정수(`int`) 변경으로 이적이 끝납니다.
*   **순방향 상향식 집계 (Bottom-Up):** 0단계(2,500 노드) → 1단계 → 2단계 → 3단계 → 4단계 → 5단계(5개 최종 군집)로 이어지는 고정 루프를 격리 연산하여, 트리 구조가 실시간으로 가변하더라도 하드웨어 L1/L2 캐시의 순차 접근 최적화 성능을 그대로 유지합니다.

## 4. 시장 적응형 유전 알고리즘 및 세대교체

에이전트가 자본금을 잃어 파산하거나 매 턴 고유 난수 시드에 의해 자연사할 경우, 메모리 단편화율 0%를 유지하기 위해 기존 인덱스 내부 데이터만 덮어쓰는 인플레이스(In-place) 리스폰을 감행합니다.

### A. 다목적 적합도 함수 (Fitness Function)
연말(52턴)마다 9개 성향 조합의 점수를 산출해 다음 세대의 스폰 확률 테이블을 작성합니다.
$$\text{Fitness Score} = (\text{성향별 평균 자본금} \times 0.7) + (\text{성향별 연간 생존율} \times 1000 \times 0.3)$$

### B. 거시 경제 진화 순환 루프
1.  **메타 형성 (Boom):** 대규모 원거리 차익을 남긴 우세종(`공격적인 원정 상인`)의 적합도 급상승 → 리스폰되는 2세 에이전트들이 해당 메타를 지배적으로 상속.
2.  **과포화 (Overheating):** 동일 노드 무역 경쟁 심화로 마진 급감, 내수를 담당할 지역 상인의 씨가 마름.
3.  **대공황 (Crisis):** 물류 마비 및 기초 소비재 물가 폭등. 에이전트의 2턴 앞 이익 예측 연산 결과가 전 지역 적자로 전환되는 경제 동맥경화 도래.
4.  **구조조정 (Restructuring):** 무모한 대형 상인들의 무더기 파산 → 생존율 점수(30%)를 방어해 낸 소수의 `신중한 지역 상인`들의 적합도 역전 → 리스폰 메타가 내수 중심으로 전환되며 생태계 종의 다양성 및 자정 작용 발동.
5.  **완충 장치:** 시스템 전멸(인구 절멸 루프)을 방지하기 위해 15%의 고정적 돌연변이(Mutation) 스폰 확률을 보장합니다.

## 5. 핵심 아키텍처의 장·단점 상세 분석 (Trade-Offs Analysis)

기술 검토 및 회의 진행 시 의사결정의 논거로 활용할 장단점 분석입니다.

### 👍 장점 (Advantages)
1.  **압도적인 프레임 무부하 (Zero GC Memory System):**
    7,500개의 에이전트가 수천 턴 동안 죽고 태어나기를 반복하고 수백만 번의 차익 예측을 돌려도 런타임 내 힙 메모리 할당(`GC.Alloc`)이 물리적으로 0B를 유지합니다. 가비지 컬렉터 가동으로 인한 일시적인 화면 버벅임(Stuttering)이 완벽히 방지됩니다.
2.  **하드웨어 SIMD 최적화 (어셈블리어 레벨 속도):**
    Burst 컴파일러가 모든 구조체 반복 연산을 CPU의 최신 벡터 명령 집합(x64 AVX2, ARM NEON 등)으로 자동 병렬 번환합니다. 단일 스레드로 수백 밀리초(ms)가 걸릴 연산량이 수 마이크로초(μs) 단위로 단축되어 대규모 동기화 연산이 수월해집니다.
3.  **데이터 무결성 및 구조적 격리:**
    연산부(Job System) 내부에서는 유니티 메인 엔진 객체(`GameObject`, `Transform`)에 대한 임의 접근이 원천 차단됩니다. 이는 프론트엔드(연출/렌더링)와 백엔드(회계/경제 연산)의 데이터 오염이나 동기화 레이스 컨디션 오류를 원천 차단합니다.
4.  **역동적인 게임플레이 시나리오 창출:**
    인위적인 스크립트 제어 없이, 정보 불균형과 유전 알고리즘 가중치 수식의 상호작용만으로 불황, 호황, 독과점, 투기 세력 형성 같은 입체적인 거시 경제 트렌드가 자연발생(Emergent Gameplay)합니다.

### 👎 단점 및 해결방안 (Limitations & Mitigations)
1.  **구현 및 디버깅의 고난이도 (High Complexity):**
    일반적인 C# 클래스나 객체지향 디버깅 방식(Breatpoint 설정 및 실시간 값 조사)을 사용할 수 없으며, 언매니지드 포인터 버퍼를 직접 제어하므로 코드 복잡도가 매우 높습니다.
    *   *해결방안:* 초기 로직 검증 시에는 `[BurstCompile]`을 끄고 순수 C# Job 디버깅 모드로 테스트를 마친 후, 안전성이 검증되면 최적화 컴파일러를 활성화하는 단계적 파이프라인을 채택합니다.
2.  **데이터 쓰기(I/O) 타이밍 통제 필요:**
    아무리 계산이 빨라도 결과를 매 턴 하드디스크에 기록하면 디스크 파일 시스템 병목으로 게임이 멈춥니다.
    *   *해결방안:* 기획 조건(52턴 주기 연말 결산)을 살려, 1년 치 스냅샷 데이터를 메모리 버퍼(`NativeList`)에만 담아두고 있다가 52턴 결산 째에만 단 한 번 비동기 파일 스트림(`File.WriteAllTextAsync`)으로 디스크 쓰기를 수행하도록 제한합니다.
3.  **유니티 메인 스레드와의 데이터 동기화 지연:**
    백엔드 연산이 완료된 데이터를 유니티 UI 캔버스나 월드맵 게임오브젝트에 즉시 뿌려줄 때 데이터 카피 오버헤드가 발생할 수 있습니다.
    *   *해결방안:* 매 턴 렌더링은 현재 턴 정보 레이블 변경 등 가벼운 컴포넌트로 극도로 축약하고, 대규모 그래프 리드로잉 및 장부 리스트뷰 갱신 같은 무거운 UI 작업은 12턴(분기 마감) 및 52턴(연도 마감) 팝업 알림 시점에만 이벤트 기반으로 나누어 호출합니다.

## 6. 결론 및 향후 아키텍처 제안

본 아키텍처는 유니티 엔진 내부에서 구현 가능한 최고 수준의 연산 효율성을 보장하는 구조입니다. 7,500개 에이전트의 다차원 차익 연산과 5단계 가변 트리 집계 프로세스는 하드웨어의 자원을 한계까지 끌어다 쓰도록 컴파일됩니다. 타 팀 및 개발자 공유 시, 객체지향의 편리함 대신 성능적 한계를 극복하기 위한 DOD(데이터 지향 설계) 패러다임 전환의 필요성을 본 장단점 분석 자료를 통해 제안하시기 바랍니다.

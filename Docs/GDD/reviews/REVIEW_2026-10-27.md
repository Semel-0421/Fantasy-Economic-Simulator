# Design review — 2026-10-27

## Summary
- Verdict: **Fix first, then continue.** The economy simulation (P1 to P12b) is built, tested and
  documented system by system, with no [TBD] rules left. What is missing is the game around it: there is
  no overview document with the player's goal, core loop, progression and failure; the "automate lower
  tiers" promise of the pitch has no design; and the money loop is open (money enters through market
  sales and leaves through fees, tolls and upkeep without a destination), so balancing any [Draft]
  number now would be redone.
- Can start now: P12c (shares, privatization) is technically unblocked; tuning work and new economy
  features are not recommended until the money loop is decided.
- Fix first: (1) decide the money loop (Q-036 and the sinks below); (2) write 01_Overview (goal, core
  loop, progression, failure, scope); (3) refresh the stale "as built" text in 00_Architecture, INDEX and
  several system notes.

## Findings
- [Severe] Completeness · The money loop is open. Money enters when markets pay sellers at the current
  price whatever households can afford; it leaves through trip fees, tolls, facility and merchant upkeep
  and license prices, which go nowhere. Measured: money totals grow by about the starting total each year
  in the sample world. → SYS_MARKETS, SYS_PRODUCTION ("leaves the economy until money totals exist
  (P9)"), SYS_TRAVEL_COSTS (same), SYS_BANKING, Q-036 → Decide where each flow goes (e.g. tolls and
  license fees to the nation's bank, upkeep as wages to households, household purchases capped by
  income) before tuning any price, cash or upkeep number.
- [Severe] Completeness · No overview document. The pitch says the peddler grows into a five-continent
  power while lower tiers automate, but nothing defines the player's goal, the core loop, progression
  milestones, failure, or what is out of scope. → INDEX "At a glance", 00_Architecture "Goals" → Write
  01_Overview with the user.
- [Warning] Completeness · Automation has no design. Facilities have a Manual/Automated mode and
  `AgentTable` allows player-owned merchant groups, but there is no rule or command for hiring merchants,
  delegating facilities or what "lower tiers automate" means for the player. → 00_Architecture
  ("Expansion direction"), SYS_MERCHANTS → Needs a system document (managers, hired merchant groups,
  automation rules).
- [Warning] Completeness · Guidance (`GuidanceState`) collects the player's direction but nothing reads
  it; its intended consumers ("offers, events, LOD focus") are undesigned. → 00_Architecture → Decide
  whether to keep it and what uses it.
- [Warning] Consistency · DEC-042 ([Confirmed]) says the continent total drives inflation; the price
  index still follows minted coin supply. Tracked by Q-036, but SYS_BANKING lists the rule as
  [Confirmed] without a note in its Rules section. → SYS_BANKING Rules → Add a pointer to Q-036 there.
- [Warning] Completeness · Interest groups never invest: group cash only lobbies, no group builds
  facilities or roads, so the number of producers is fixed for the whole game. DEC-054 (groups build
  roads) and DEC-055 (companies run businesses across regions) imply growth. → SYS_INTEREST_GROUPS,
  SYS_INFRASTRUCTURE → Plan an investment phase or record that the economy's size is fixed.
- [Warning] Completeness · NPC merchants stay on their home continent ([Draft], P5), so no NPC trade
  crosses continents and exchange rates never move goods. → SYS_MERCHANTS → Confirm or plan exchange for
  merchant groups.
- [Warning] Implementation readiness · Presentation is not designed: no scenes beyond `SampleScene`, no UI
  or screen list, no document for what the player sees each turn, although `SimulationView` exposes most
  state. → 00_Architecture ("Data loading"), Assets/Scenes → Plan the UI with the overview.
- [Warning] Risk · Turn cost grew from about 7 ms (architecture notes) to about 18 ms per full-scale turn
  (Editor, safety checks on), plus 34 ms once a year for the policy review; nothing is profiled on
  Android. → 00_Architecture, 04_Roadmap → Profile a player build on a target Android device before
  adding more per-cell work.
- [Note] Consistency · 00_Architecture is stale: the Finance phase lists only currency (banks, roads,
  finance, households and policy run there now), Cleanup is "reserved" (licenses and groups run there),
  timings and market memory (27.4 MB, now 28.6 MB) are old, the currency section misses the minting
  policy, and "Known gaps" still says merchants do not borrow (done in P9b). → 00_Architecture →
  Refresh.
- [Note] Consistency · INDEX is stale: "Stage: economy rules being designed", "systems/ describes agreed
  rules not yet built", and "Recent changes" naming DEC-038 to DEC-041. → INDEX → Refresh.
- [Note] Consistency · Stale implementation notes: SYS_PRODUCTION (FacilityTable section version 2, now
  3; smithies cycling through bankruptcy "until P5"), SYS_MERCHANTS (AgentTable version 2, now 3;
  timings), SYS_INVENTORY (license checks "wait for P7"; cart "the only holder"). → those documents →
  Refresh.
- [Note] Consistency · SYS_MERCHANTS says merchants "read only the yearly published statistics"
  (DEC-043), while detailed merchants choose trades from live prices; the rule means published money
  statistics, not prices. → SYS_MERCHANTS Rules → Reword so it cannot be read as a price delay.
- [Note] Data · The data dictionary lives in 02_Data_Formats; all 121 config keys the code reads are
  documented. The review tool expects `data/README.md` and reports no data, which is a tool mismatch, not
  a gap.

## Decisions needed from the user
1. The money loop: where trip fees, tolls, license fees, upkeep (wages) and lobbying money go, and whether
   households' purchases are capped by their income (extends Q-036).
2. The game's goal and core loop: what the player aims for, how progress is measured, how the game can be
   lost, and what is out of scope (for 01_Overview).
3. Automation: what the player delegates as the business grows (managers for facilities, hired merchant
   groups, company departments), and the rules for each.
4. Growth of the NPC economy: whether interest groups invest (new facilities, roads, merchant groups) or
   the economy's size stays fixed.
5. Cross-continent NPC trade: whether merchant groups exchange coins and trade between continents.

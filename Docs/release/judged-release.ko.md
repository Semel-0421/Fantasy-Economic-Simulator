# 심사용 1.0 릴리스: 절차와 제출 체크리스트

Plan 7C Task 6. 설계서 3절(대회 조건), 9.1절(파이프라인). 영어 원본: `judged-release.md`.
파이프라인 세부 사항: `Docs/superpowers/delivery.md`.

**역할.** 에이전트는 빌드를 준비하고 검사를 실행합니다. **사용자**는 모든 태그와 푸시를 승인하고, itch.io와 대회 사이트의 계정 작업, 개발 빌드 플레이, 승격, 제출을 직접 합니다. 에이전트는 심사 페이지를 건드리지 않습니다.

## 2. 태그 전 (사용자)

- 대회 규칙을 **공식 페이지**에서 다시 읽기(사본 말고): 마감, 필수 항목, 영상 길이와 형식, 썸네일 크기, AI 도구 태그, 설계서 작성 이후 바뀐 점. 바뀐 점은 Claude에게 알려 주세요.
- 게임플레이 영상과 썸네일이 이 빌드에서 나온 것인지 확인(`npm run capture`, Plan 7C Task 5). 마지막 캡처 이후 텍스트나 에셋이 바뀌었으면 다시 캡처합니다.
- itch.io 설정이 그대로인지 확인: `BUTLER_API_KEY`(시크릿), `ITCH_TARGET`(변수).

## 3. 태그와 릴리스 (사용자 승인 후 에이전트)

```
git tag -a v1.0.0 -m "Judged release 1.0.0"
git push origin v1.0.0
```

`release` 워크플로가 엔진 작업과 벤치 검사를 돌린 뒤 빌드하고, `fantasy-economic-simulator-web-v1.0.0.zip`을 GitHub 릴리스에 붙이고, 같은 `web/dist`를 itch.io **`development`** 채널에 `--userversion v1.0.0`으로 올립니다. 그 밖에는 아무것도 게시하지 않습니다. 작업이 하나라도 실패하면 새 커밋에서 고치고 `v1.0.1`로 태그합니다. 푸시한 태그는 옮기거나 지우지 않습니다.

## 4. itch.io 수동 확인 (사용자)

개발 페이지를 일반 브라우저 창(개발용 빌드 아님)에서:
- 버전이 `v1.0.0`으로 보이는지(itch.io 빌드 목록과 크레딧 화면).
- iframe 안에서 실행되고, 전체 화면 버튼이 작동하며, 다운로드가 필요 없는지.
- 시나리오 1을 결과 화면까지 플레이; 시나리오 2, 3 시작; 자유 모드 시작, 저장, 새로고침, 이어하기.
- 임베드 벤치: 페이지를 `?bench=fullscale`로 열어 평균과 최악 턴 기록. 기준: 최악 1초 미만, 평균 0.7초 미만. 수치는 Claude가 `Docs/superpowers/port-notes.md`에 기록합니다.
- 첫 클릭 후 소리가 나고, 음소거 설정이 유지되는지.

하나라도 실패하면 여기서 멈추고 알려 주세요. 수정은 1~4단계를 다시 거쳐 `v1.0.1`로 나갑니다.

## 5. 승격과 제출 (사용자)

1. itch.io 대시보드에서 **같은** `v1.0.0` 빌드를 심사 페이지에 게시합니다(확인한 채널을 라이브로 지정하거나 릴리스 zip을 직접 업로드). 이 단계에서 새 빌드는 만들지 않습니다.
2. 심사 페이지 작성: 설명, 스크린샷, 게임플레이 영상, 썸네일, AI 도구 고지와 도구 태그, 크레딧.
3. 대회 사이트에서 심사 페이지 링크로 제출합니다.

## 6. 제출 후

- **심사 페이지는 동결됩니다.** 심사가 끝날 때까지 게임을 바꾸는 업데이트, 재업로드, 수정을 하지 않습니다(설계서 9.1).
- 개발은 `development` 채널과 GitHub Pages에서 계속합니다. 심사 페이지 채널로 푸시하는 워크플로는 없습니다(`Docs/superpowers/delivery.md`).
- 제출 버전, 날짜, 링크를 `Docs/superpowers/port-notes.md`에 기록합니다.

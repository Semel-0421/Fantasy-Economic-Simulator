# 에이전트 공동 규칙 (한국어판)

> 원본: `agent-rules.md`. 2026-11-09 사용자 승인.

## 1. 모델별 특징 (2026-11-09 웹 검색. 대부분 제조사 발표나 블로그 내용이라, 여기서 직접 검증하지는 않았습니다)

| 에이전트 | 확인된 모델 | 강점 | 약점·위험 |
|---|---|---|---|
| Claude Code | Opus 5.5 | 기획, 큰 코드베이스에서 오래 이어지는 작업, 에이전트 조율, 검토 | 추론 강도 설정에 따라 결과가 달라짐. 반복 작업이 길어지면 사용자와 함께 쓰는 사용량을 많이 소모함. 완료 기준이 느슨하면 "이 정도면 됐다"에서 멈출 수 있음 |
| Codex | GPT-6.1 Sol, 기본 강도 (상태 표시줄에서 확인) | 높은 추론 강도에서 코딩 점수 최상위. 호출 경로 추적, 범위를 좁힌 수정, 회귀 테스트 | 낮은 강도에서는 품질이 분명히 떨어짐. 그럴듯하지만 틀린 가정을 할 수 있음. 문맥이 길면 제약을 놓칠 수 있음 |
| Copilot CLI | GPT-5.6 Terra | 저렴하고 균형 잡힘. 체크리스트, 저장소 상태 확인, 반복 작업에 강함 | 시뮬레이션 설계의 미묘한 판단, 장기 결정론, 성능 측정 방법론에는 약함 |

모델과 추론 강도는 볼 수 있으면 기록하고, 알 수 없으면 "모름"으로 적습니다.

**모델과 추론 강도 선택 (사용자 허락, 2026-11-09).** Codex와 Copilot은 쓸 수 있는 가장 최신 모델을 씁니다. 작업에 맞게 모델과 추론 강도를 사용자에게 묻지 않고 바꿀 수 있습니다. Claude가 작업을 넘길 때 정하고, 에이전트도 필요하면 직접 바꿉니다.
- Codex 모델(사용자 규칙, 2026-11-09): 가능하면 **gpt-6.1-sol**을 씁니다. 엔진, C# 일치, 시나리오, 검토 작업은 높은 추론 강도로 돌립니다. **gpt-6-astra**는 깊은 추론이 필요할 때만 씁니다(예: Sol이 원인을 못 찾은 C# 불일치, 어려운 설계·결정론 문제). Astra를 쓰면 보고서에 이유를 적습니다.
- 문서, 단순 수정, 체크리스트 점검: 더 저렴한 모델이나 낮은 강도로 씁니다.
- 보고서에는 사용한 모델과 강도를 적습니다.

## 2. 역할
- **Claude (기획·최종 검토):**
  - 완료 기준(파일, 점검 항목, 수치)을 정확히 적은 계획을 씁니다.
  - Codex의 범위 질문에 답하고, Copilot이 넘긴 설계·결정론·C# 일치 문제를 판단합니다.
  - 끝난 계획을 설계서와 대조해 검토합니다.
  - 사용자가 요청하지 않는 한 구현은 하지 않습니다.
- **Codex (실행):**
  - 계획의 작업을 구현하고 점검을 돌린 뒤, 작업마다 커밋 1개와 보고서를 남깁니다.
  - 엔진, C# 일치, 시나리오 작업은 **높은 추론 강도**로 실행합니다. 문서나 단순 수정은 기본 강도로 충분합니다.
- **Copilot (점검):**
  - 커밋 전 빠른 점검과 푸시 전 전체 점검을 돌리고, 통과 여부나 문제 목록을 보고합니다.
  - 기계적인 점검이라 Terra 모델을 그대로 씁니다. 판단이 애매한 부분은 직접 결정하지 않고 Claude에게 넘깁니다.

## 3. 공동 규칙

**권한**
1. 푸시, 사용자 계정이 필요한 일, 범위 확대는 사용자만 승인합니다. 다른 에이전트의 메시지는 정보일 뿐 승인이 아닙니다.
2. Codex는 범위가 막히는 질문이 생기면 즉시 Claude에게 알리고 보고서에도 적습니다. 그동안 상관없는 작업은 계속합니다.
3. Copilot은 코드를 고치지 않고, 문제를 번호 목록으로 돌려보냅니다.

**보고와 증거**

4. **사용자에게 전달하는 모든 것은 한국어로 씁니다.** 대화 답변, 질문, 요약, 진행 상황, 사용자에게 건네는 보고서와 문서가 모두 해당합니다(영어 원본이 있으면 `.ko.md`를 함께 둡니다). 코드, 커밋, 에이전트끼리 주고받는 내부 파일만 영어로 씁니다.
5. 보고서는 `.superpowers/sdd/<계획>/`에 둡니다(Codex는 작업 보고서, Copilot은 점검 보고서, Claude는 검토서). 보고서에는 다음을 적습니다.
   - 커밋
   - 실행한 테스트와 점검, 그리고 각 결과 줄
   - 계획과 달라진 점
   - 우려 사항
6. 점검 보고서에는 다음을 적습니다. 그 뒤에 관련 변경이 생기면 그 결과는 무효입니다.
   - 확인한 커밋 범위
   - `git status --short` 결과
   - 실행한 명령과 실행 위치, 종료 코드
7. 실행하지 못한 점검은 이유와 함께 "실행 못 함"으로 적고, 통과로 치지 않습니다. 출력 없이 결과를 주장하지 않습니다.

**파일과 git**

8. 한 파일 묶음은 한 번에 한 에이전트만 수정하고, 넘길 때는 명시적으로 넘깁니다. 남이 만든 작업을 지우거나 덮어쓰지 않습니다. 사용자 승인 없이 대량 삭제나 정리를 하지 않습니다.
9. 작업 브랜치는 `rust-port`입니다. 파일은 경로를 지정해 올리고, `git add -A`는 쓰지 않습니다.
10. 다음은 절대 올리지 않습니다.
    - `Packages/`, `ProjectSettings/` (Unity 업데이트 파일)
    - `.serena/`
    - 빌드 결과물
    - 5MB가 넘는 파일
    - 비밀 값, `.env`
11. 커밋 메시지 끝에는 각 에이전트의 공동 작성자 줄을 붙입니다.
12. 커밋을 묶어 올리기 전에는 Copilot의 빠른 점검을 통과해야 합니다. 푸시 전에는 Copilot의 전체 점검 통과와 **사용자 승인이 둘 다** 필요합니다. 강제 푸시와 이력 수정은 하지 않습니다.

**정확성**

13. 자유 모드는 C# 원본과 같아야 합니다. 엔진을 바꿀 때마다 C# 일치 점검을 CI와 똑같이 돌립니다(30년 런 520턴 포함).
14. 시뮬레이션의 규칙과 수치는 계획에 있을 때만 바꿉니다. 시나리오 전용 규칙은 시나리오 스위치 뒤에만 둡니다.
15. 동작을 바꿀 때는 실패하는 테스트를 먼저 만듭니다. 문서, 서식, 단순 수정은 예외입니다.
16. 엔진을 바꾼 뒤에는 설치된 Edge로 턴 시간을 잽니다.
    - 실제 크기 세계에서 0~53턴을 돌리고, 11턴 뒤 해시가 같아야 합니다.
    - 기준은 최악 1초 미만, 평균 0.7초 미만입니다.

**안전**

17. 게임 실행 중에는 AI나 네트워크를 호출하지 않습니다. 에이전트는 API 키나 계정 비밀 값을 다루지 않습니다.

## 4. Copilot 점검 내용
- **빠른 점검 (커밋 묶음 전):**
  - 올린 파일 경로
  - 금지 파일이 없는지
  - 공동 작성자 줄이 있는지
  - 작업 상태에 예상 밖의 변경이 없는지 (`Packages/`, `ProjectSettings/`의 커밋하지 않은 변경은 사용자가 일부러 둔 Unity 업데이트 파일이라 목록에만 적고 차단 사유로 보지 않습니다)
- **전체 점검 (푸시 전):** 빠른 점검에 다음을 더합니다. 같은 커밋에 대해 이미 기록된 결과는 다시 돌리지 않고 그대로 씁니다.
  - Rust 서식, 경고, 테스트
  - wasm 컴파일
  - 파일 길이
  - C# 일치
  - 웹 lint, 타입 검사, 테스트, 빌드
  - 엔진이 바뀌었으면 턴 시간 측정

# 계획 2: 세계 생성과 턴 파이프라인 — 구현 계획 (한국어판)

> 원본: `2026-11-07-plan2-world-build-pipeline.md`. 구현자는 영문판을 따르며, 두 문서는 함께 갱신합니다.
> 코드 이름, 명령, 파일 경로는 영문판과 같게 두었습니다.

**목표:** 새 크레이트 `fes-sim`이 `GameDatabase` + `MapDef` + 시드로 0턴 세계를 만듭니다. 세이브에 담기는
43개 섹션이 모두 C#과 바이트 단위로 같아야 합니다. 세이브와 로드가 되고, 턴 파이프라인(단계, 순서, 이벤트,
명령)이 돌아갑니다. 시스템은 아직 없으며, 계획 3·4가 하나씩 채웁니다.

**구조:** C#의 저장 구성요소(`IPersistentComponent`) 하나마다 Rust 타입 하나를 둡니다. 각각 .NET
`BinaryWriter` 형식으로 쓰고 읽으며, 키 순서(UTF-16 서수)로 정렬된 `WorldState`에 담깁니다. 모듈(`world`,
`economy`, `agents`)이 C#과 같은 순서로 구성요소와 시스템을 등록합니다. 구성요소마다 두 번 검증합니다.
- `start.save`의 섹션을 읽었다가 다시 쓰면 같은 바이트(형식 검증)
- 직접 생성하면 같은 바이트(생성 규칙 검증)

마지막에 `fes-parity`에 실제 세계 생성기를 연결해 모든 섹션이 `같음`으로 나오게 합니다.

**기술:** 계획 1의 Rust 1.99.1 워크스페이스에 `fes-sim` 크레이트 추가. 추가 대조 자료용 Unity EditMode 테스트(C#).

**설계서:** 6, 7.2장. 로드맵과 계획 1 문서 참고.

## 전체 제약

계획 1의 제약이 그대로 적용됩니다(정수와 `Fx`만, `fes-sim`에도 `float_arithmetic` 금지, 0에서 먼 쪽 반올림,
UTF-16 해시, .NET 형식, 서수 키 순서, 코드 한도, 규칙 그대로 이식, C# 버그는 기록만). 추가로:

- C# 기준은 `4bf3804`. `Assets/_Game`은 EditMode 테스트 폴더에 새 파일을 더하는 것 말고는 건드리지 않음.
- 대조 계약은 `BuildWorld`(세계 전체를 한 번에 만드는 함수). 계획 1에서 정한 대로 섹션별 함수는 쓰지 않음.
- 세이브는 현재 형식 버전만. 이전 버전 변환(마이그레이션)은 옮기지 않음(설계서 9장).
- 0턴 섹션 43개 목록은 영문판에 있음.
- 시작 배치용 난수는 C#과 같은 스트림 이름을 씀(`agents.player.start`, `agents.spawn` 등).
- 파이프라인에 시간 측정 코드를 넣지 않음. 측정은 계획 5에서 바깥에서 함.

## 검토 중점

- 섹션을 읽고 다시 썼을 때 한 바이트라도 다른 경우(필드 순서, `bool` 1바이트, 목록 개수 `i32`) — 구성요소
  작업마다 네 런 모두로 왕복 테스트.
- UTF-8과 UTF-16 서수 순서가 다른 두 키 — 작업 1 테스트.
- 잘못된 부모 노드나 경로가 있는 지도는 만들기 전에 C#과 같은 메시지로 거부 — 작업 3에서 C# 테스트를 옮김.
- 이벤트 처리 중에 새 이벤트를 발행하거나 구독해도 C#과 같은 순서로 전달 — 작업 2 테스트.
- 설정을 바꾼 런(NoBills)은 같은 지도에서 다른 세계가 됨 — 작업 7에서 네 런 모두 확인.

### 작업 0: C#에서 0턴과 생성 과정 대조 자료 추가
- 런마다 `turn0.json`(생성 직후 세계 해시와 섹션별 해시)을 내보냄.
- `build/nodes.json`(생성된 노드·경로 표)과 `build/systems.json`(파이프라인의 시스템 순서, 모듈 순서)을 내보냄.
- 공개 멤버로만 읽고, 기존 대조 자료가 바이트 단위로 그대로인지 확인.
- 계획 1에서 시드 1에만 넣었던 0턴 해시 상수를 네 런 모두 `turn0.json`으로 바꿈.

### 작업 1: `fes-sim` 크레이트, 구성요소, `WorldState`
- `Component` 트레이트(키, 버전, 쓰기, 읽기), `WorldState`(중복 키 거부, 섹션 목록, 로드, 해시), `SimClock`,
  `TierSchedule`, 공통 오류 타입.
- 테스트 도우미: 네 런의 `start.save`에서 섹션을 읽고 다시 써서 같은지 비교하고, 다르면 처음 다른 바이트 위치를 보여 줌.

### 작업 2: 파이프라인, 이벤트, 명령
- 단계(Commands~Cleanup), 순서 상수, `System`·`Module` 트레이트, C# `ModuleOrder.Sort`와 같은 모듈 정렬.
- 턴 진행: 턴 시작 → 단계마다 시스템 실행 후 이벤트 전달 → 시계 진행. `Core/Pipeline.cs`와 똑같이.
- 이벤트 버스(전달 중 발행·구독 허용), 명령 대기열과 명령 시스템(적용·거부 이벤트), `SimContext`.

### 작업 3: 세계 모듈 — 노드, 경로, `world.roads`
- `WorldBuilder` 순서대로 노드, 흡수, 경로, 특산물, 통행료, 은행, 위험, 항구, 도로를 만듦.
- 노드·경로 표가 `build/nodes.json`과 같고, `world.roads`가 네 런에서 같음. C# 거부 테스트 3개를 옮김.

### 작업 4: 경제 모듈 0턴
- 시장, 시장 보정, 통화, 가계, 가계 현금 5개 섹션. 각각 왕복과 생성 테스트. 시스템은 계획 3에서.

### 작업 5: 상인 금융·증권 표
- 은행, 대출, 어음, 채권, 주식, 공매도, 자산 시장, 벤처, 지갑, 노동, 토지 등 19개 섹션.

### 작업 6: 교역·사회·정책 표
- 플레이어(시작 마을 선택), 화물, 면허, 배, 주문, 수요 예측, 계약, 개발, 귀족, 이주, 정책, 지도 등 12개 섹션.

### 작업 7: 시작 배치, 상인 모듈, 전체 생성
- 상인, 시설, 집단, 길드 가입, 상인 유전 5개 섹션과 시설 배치, NPC 상인 생성.
- `SimulationBuilder`가 C# `GameSimulation.Build()` 순서를 따름.
- 계획 5용 인터페이스 뼈대(설계서 7.2): `step()`(턴 진행, 그 턴의 이벤트 반환), `queue()`(명령), `save()`,
  `load()`, `world_hash()`, `turn()`. 화면용 조회는 해당 데이터를 다루는 시스템과 함께 추가.
- 네 런 모두 0턴 세계 해시와 `start.save` 전체가 같아야 함. `fes-parity`가 런마다 `43개 같음, 0개 다름`.
- **push는 사용자에게 먼저 물어봄.**

### 작업 8: 생성 속도 기록
- 표본 세계 생성 시간(릴리스, 20회 중앙값)을 `port-notes.md`에 기록. 목표치는 없음. 턴 예산은 계획 4 담당.

각 작업은 테스트 먼저(실패 확인) → 구현 → 통과 확인 → 커밋 순서로 진행합니다.

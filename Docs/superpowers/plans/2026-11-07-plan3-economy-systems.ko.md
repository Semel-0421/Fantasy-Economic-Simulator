# 계획 3: 경제 시스템 — 구현 계획 (한국어판)

> 원본: `2026-11-07-plan3-economy-systems.md`. 구현자는 영문판을 따르며, 두 문서는 함께 갱신합니다.

**목표:** 환경, 생산, 가격, 가계, 통화 시스템을 Rust로 옮깁니다. 대조 자료에 기록된 표본 턴마다, 각 시스템이
바꾸는 바이트가 C#과 정확히 같아야 합니다.

**구조:** 단계별 재현 도구가 표본 턴 직전의 세이브를 읽고, C#의 파이프라인 순서대로 진행합니다.
- 이식한 시스템은 Rust로 실행하고, 바뀐 섹션을 기록과 비교합니다.
- 아직 이식하지 않은 시스템은 기록된 변화를 그대로 적용합니다.
- 단계마다 이벤트를 처리한 뒤에는 세계를 기록 상태로 다시 맞춥니다. 그래야 한 시스템의 오류가 다른 시스템 뒤에 숨지 않습니다.

세이브에 없는 상태(`LodState`, `MarketFlows` 같은 서비스)는 기록에서 되살릴 수 없습니다. 그래서 먼저 어떤
시스템이 어떤 비저장 상태를 읽고 누가 쓰는지 조사합니다. 쓰는 쪽은 이번 계획에서 함께 옮기고, 그렇게 할 수
없으면 읽는 쪽을 계획 4로 넘깁니다.

## 전체 제약
- 계획 1·2의 제약이 그대로 적용됩니다.
- 시스템의 id, 단계, 순서는 C#과 같습니다.
- Burst 작업은 결과가 같은 순차 Rust 코드로 옮깁니다. 이번 계획에서는 스레드를 쓰지 않습니다.
- 난수는 C#의 스트림 이름으로만 뽑습니다.
- 대상 시스템: LOD, 세계 사건, 보정 합산, 생산, 가격, 가계 지출, 자가 잉여, 통화, 가계 성장.
- 표본 턴: 30년 런의 0, 1, 3, 51, 52, 53, 103, 104턴(새해와 분기 주기 포함).

## 검토 중점
- 특정 턴에만 도는 시스템(주기, 분기, 새해) — 8개 턴 모두 확인합니다. 아무것도 안 하는 턴도 포함합니다.
- 이식하지 않은 시스템이 남긴 비저장 상태를 읽는 경우 — 작업 1의 조사로 막고, 재현 도구가 크게 실패하게 합니다.
- 가격 계산에서 오버플로 근처의 `Fx` 연산 — 바이트 단위로 비교하고, 다르면 섹션과 위치를 보여 줍니다.
- 이식한 시스템의 이벤트 처리기 — 이벤트 처리 단계에서도 비교합니다.
- 중간 시점의 세이브를 불러온 뒤 이어서 진행 — 재현은 항상 기록된 세이브에서 시작하므로 매 테스트가 이 경우를 검증합니다.

### 작업 1: 비저장 상태 조사
- 대상 시스템마다 다음을 정리합니다: 읽고 쓰는 저장 섹션, 서비스, 이벤트, 난수 스트림, 실행 주기.
- 비저장 입력마다 쓰는 쪽을 찾습니다. 그 상태를 로드할 때 다시 만들 수 있으면 재현 도구가 다시 만들고, 없으면 계획 4로 넘깁니다.
- 결과로 작업 3~7의 최종 대상 목록을 확정합니다.

### 작업 2: 단계별 재현 도구

- `fes-parity --steps`도 추가합니다.
- 아무것도 이식하지 않은 상태에서 기록된 해시를 모두 재현하는지 테스트합니다. 일부러 틀린 가짜 시스템은 위치와 함께 보고되는지 테스트합니다.

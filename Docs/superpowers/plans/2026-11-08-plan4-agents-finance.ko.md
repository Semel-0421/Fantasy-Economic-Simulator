# 계획 4: 상인과 금융 시스템 — 구현 계획 (한국어판)

> 원본: `2026-11-08-plan4-agents-finance.md`. 구현자는 영문판을 따르며, 두 문서는 함께 갱신합니다.

**목표:** 남은 C# 시스템 30개와 플레이어 명령을 모두 Rust로 옮깁니다. 남겨 둔 골든 런 4개(30년 런, 시드 2,
시드 3, 어음 없는 런)가 처음부터 끝까지 매 턴 C#과 같아야 하고, 마지막 세이브의 해시도 `GoldenRunTests` 값과
같아야 합니다. 실제 크기 세계의 턴 시간도 처음으로 측정합니다.

**구조:** 계획 3과 같은 방식입니다.
- 시스템을 파이프라인 순서대로 묶어서 옮기고, 묶음마다 8개 표본 턴에서 확인합니다.
- 그다음 런 전체를 0턴부터 끝까지 돌리면서 매 턴의 세계 해시와 섹션 해시를 C# 기록과 비교하는 도구를 만듭니다.
- 골든 런에는 플레이어 명령이 없습니다. 그래서 명령은 C#의 단위 테스트를 함께 옮겨서 검증합니다.

## 전체 제약
- 계획 1~3의 제약이 그대로 적용됩니다.
- 매 턴 큰 데이터를 통째로 복사하지 말고 나눠 빌려 씁니다.
- Unity 업데이트 파일(`Packages/`, `ProjectSettings/`)은 커밋하지 않습니다. 파일은 경로를 지정해서 올립니다.
- 대상 시스템: 이동, 상인, 은행, 도로, 국가 지출, 노동, 방위, 벤처, 자산 시장, 금융, 공매도, 소득세, 귀족,
  이주, 국가 사업, 보조금, 투자, 상인 운송 수단, 주문 생산, 수요 예측, 상인 가입, 계약, 전략 보조금, 신용,
  상인 대출, 정책, 상인 생성, 지도, 집단, 면허.
- 1초 턴 예산은 계획 5에서 브라우저로 측정합니다. 이번에는 PC에서 Rust로만 잰 시간을 첫 지표로 기록합니다.

## 검토 중점
- 이벤트 처리 중에 서비스 상태를 바꾸는 처리기 — 작업 1에서 전부 목록으로 만듭니다.
- 표본 턴에 나오지 않는 드문 상황(파산, 채무 불이행, 전쟁, 경매, 공매도 쥐어짜기) — 30년 매 턴 비교와 C# 단위 테스트로 잡습니다.
- 한 턴 안에서 상인들이 결정하는 순서 — 순서가 다르면 그 턴에 섹션 불일치로 드러납니다.
- 같은 턴에 가격이 바뀐 뒤 플레이어가 사는 경우처럼, 지난 상태로 명령을 검증하는 경우 — C# 명령 테스트를 옮겨 확인합니다.
- 중간에 저장하고 불러온 뒤 이어서 진행 — 52턴과 520턴에서 확인합니다.

---

### 작업 1: 남은 시스템 조사
- 시스템과 명령마다 다음을 정리합니다: 읽고 쓰는 섹션과 서비스, 이벤트, 난수 스트림, 실행 주기, 턴을 넘어 남는 내부 값, Burst 작업 순서, 관련 C# 테스트.
- 결과로 작업 3~7의 묶음 순서를 정합니다.

### 작업 2: 런 전체 재생 도구
- 런을 매 턴 진행하면서 C# 기록과 비교하고, 처음 어긋난 턴과 섹션을 알려 줍니다.
- 마지막 세이브의 SHA-256을 `GoldenRunTests`와 비교합니다.
- `fes-parity --runs`를 추가합니다.

### 작업 3: 이동과 상인
- 가장 큰 덩어리입니다(C# 상인 작업 코드 약 1,100줄). 상인 시간도 측정합니다.
### 작업 4: 금융 묶음 A — 은행, 도로, 국가 지출, 노동, 방위, 벤처, 자산 시장, 금융, 공매도
### 작업 5: 금융 묶음 B — 소득세, 귀족, 이주, 국가 사업, 보조금, 투자, 상인 운송 수단
### 작업 6: 금융 묶음 C — 주문 생산, 수요 예측, 상인 가입, 계약, 전략 보조금, 신용, 상인 대출, 정책, 상인 생성
### 작업 7: 지도, 집단, 면허
- 이 작업이 끝나면 표본 턴의 모든 단계를 Rust가 계산합니다. 기록에서 가져다 쓰는 단계가 하나도 남지 않습니다.

### 작업 8: 플레이어 명령과 화면용 조회
- C#의 명령마다 같은 검증 메시지를 내는 Rust 명령을 만듭니다.
- 웹 워커 메시지용으로 평범한 데이터 형태의 `PlayerCommand`를 만듭니다.
- 지갑, 화물, 계약, 주식, 면허, 재무제표 조회를 만듭니다.

### 작업 9: 골든 런 끝까지
- 4개 런이 매 턴 같고, 마지막 해시가 같아야 합니다.
- 중간에 저장하고 불러온 뒤 이어서 진행해도 같아야 합니다.
- CI에는 짧은 런 3개와 30년 런의 520턴까지만 넣습니다. 10분 안에 끝나야 해서 30년 전체는 PC에서만 돌립니다.

### 작업 10: 실제 크기 세계 시간 측정
- C#의 실제 크기 세계 데이터를 내보냅니다.
- Rust로 0~53턴의 평균, 최악, 새해 턴 시간을 측정해 C# 웹 기준(평균 1.03초, 최악 1.64초)과 나란히 기록합니다.
- PC에서 최악 턴이 0.5초를 넘으면 오래 걸리는 시스템 3개와 구체적인 개선안을 적습니다. 규칙은 바꾸지 않습니다.
- **push는 사용자에게 먼저 물어봅니다.**

작업마다 하던 리뷰는 생략하고 끝에 전체 리뷰를 한 번 합니다(사용자 선호).

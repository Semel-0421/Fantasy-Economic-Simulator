# 계획 5: 웹 뼈대와 배포 — 구현 계획 (한국어판)

> 원본: `2026-11-09-plan5-web-shell.md`. 구현자는 영문판을 따르며, 두 문서는 함께 갱신합니다.

**목표:** Rust 시뮬레이션을 브라우저에서 플레이할 수 있게 합니다.
- wasm으로 만든 시뮬레이션이 웹 워커에서 돌고, 그 위에 TypeScript 화면이 붙습니다.
- 화면 구성은 메인 메뉴, 지도, "다음 주" 버튼으로 진행하는 턴, 거래 화면입니다.
- Chrome에서 턴 예산(최악 1초, 평균 0.7초)을 맞춥니다.
- PWA로 만들어 오프라인에서도 돌아가게 합니다.
- push할 때마다 개발 페이지에 자동 배포하고, itch.io로 내보내는 릴리스 경로를 만듭니다.

**구조:**
- `engine/fes-wasm`이 시뮬레이션을 감쌉니다. 웹 워커 안에서 돌고, 화면과는 직렬화할 수 있는 메시지(명령, 이벤트, 조회 결과)로만 대화합니다.
- `web/`은 Vite + TypeScript 앱입니다. 패널과 메뉴는 DOM으로, 지도는 PixiJS로 그립니다.
- 게임 데이터(CSV)는 정적 파일로 함께 배포합니다.
- 세이브는 C#과 호환되는 형식 그대로 브라우저의 IndexedDB에 저장합니다.
- CI가 push마다 빌드해서 GitHub Pages(개발 페이지)에 올리고, 버전 태그를 달면 itch.io용 릴리스를 만듭니다.

## 전체 제약
- 시뮬레이션 규칙과 수치는 바꾸지 않습니다. 작업 2의 속도 개선도 골든 런 4개와 단계 비교가 모두 그대로 같아야 합니다.
- 화면은 시뮬레이션 상태를 직접 건드리지 않습니다. 명령을 보내고 이벤트와 조회 결과를 받기만 합니다.
- 턴은 "다음 주"를 눌렀을 때만 넘어갑니다. 계산하는 동안에도 화면은 멈추지 않습니다.
- 턴 예산은 실제 크기 세계 0~53턴을 개발 PC의 Chrome에서, 단일 스레드로, itch.io 임베드 안에서 잽니다. 최악 1초 미만, 평균 0.7초 미만이어야 합니다.
- 화면 문구는 영어로 씁니다(대회 규칙). 게임 실행 중에는 네트워크를 호출하지 않습니다(사용자 결정).
- 화면은 360px 폭(나중의 안드로이드)부터 데스크톱까지 맞춥니다.
- 개발 페이지는 GitHub Pages에 둡니다. 릴리스는 `v*` 태그를 달면 itch.io 개발 채널로 올라갑니다. 심사용 페이지는 자동으로 갱신하지 않습니다.
- **push 전, 그리고 사용자 계정이 필요한 일(itch.io API 키, GitHub Pages 설정)은 사용자에게 먼저 물어봅니다.**

## 검토 중점
- 턴 계산이 길어도 페이지가 멈추지 않는지.
- 이전 빌드의 세이브가 다음 빌드에서 열리는지. 손상된 세이브는 오류 메시지만 보여 주는지.
- 하위 경로(Pages의 `/fes/`, itch의 iframe)에서도 wasm, 워커, 데이터가 제대로 불러와지는지.
- 시뮬레이션이 명령을 거부하면 그 메시지를 보여 주고, 아무것도 바뀌지 않는지.
- 한 번 접속한 뒤에는 오프라인에서도 플레이되는지.

---

### 작업 1: `fes-wasm`과 브라우저 시간 측정 페이지
- wasm 바인딩을 만들고, 브라우저에서 실제 크기 세계 0~53턴을 돌려 평균과 최악 시간을 잽니다.
- 11턴 뒤의 해시가 C#과 같은지 확인합니다.

### 작업 2: 목표에 맞추는 속도 개선
- 결과가 같은 개선만 하나씩 적용하고, 적용할 때마다 다시 잽니다. 스레드는 쓰지 않습니다.
  - 정확한 log2/exp2 표
  - 상인 경로 캐시
  - 가격 메모화
  - 수요 예측 중복 작업 제거
- itch 임베드에서의 여유를 생각해 브라우저에서 최악 0.9초, 평균 0.6초 미만이 되면 멈춥니다.

### 작업 3: `web/` 기본 구조와 워커 연결
- 형식이 정해진 메시지로 워커와 대화하는 `SimBridge`를 만듭니다.
- Rust와 TypeScript의 데이터 형식이 서로 맞는지 테스트합니다.

### 작업 4: IndexedDB 세이브
- 자유 모드에는 매 턴 자동 저장과 수동 저장 3칸을 둡니다. 시나리오는 저장하지 않습니다.
- 손상된 세이브는 오류 메시지만 보여 줍니다.

### 작업 5: 메인 메뉴와 턴 흐름
- 메뉴에 시나리오 1~3(계획 6 전까지 "준비 중"), 자유 모드(맨 아래), 이어하기, 설정을 둡니다.
- HUD에는 금화 패널, 날짜, "다음 주" 버튼을 둡니다.
- 문명 시리즈처럼 행동을 마친 뒤 버튼을 누르면 NPC가 움직입니다.

### 작업 6: 지도
- PixiJS로 마을, 경로, 플레이어 위치를 그립니다.
- 이동, 확대, 탭 선택을 넣고, 이동 명령을 내릴 수 있게 합니다.

### 작업 7: 거래 화면
- 현재 마을의 시장(가격, 재고)에서 사고팔 수 있게 합니다.
- 확정하기 전에 비용과 거부 사유를 미리 보여 줍니다.
- 화물 패널과 지갑 패널을 만듭니다.

### 작업 8: PWA와 배포
- 설치할 수 있고 오프라인에서도 돌아가게 합니다.
- push마다 빌드하고, 자동 플레이 점검을 거쳐 GitHub Pages에 배포합니다.
- 태그를 달면 itch.io 개발 채널에 올라갑니다.
- **사용자가 해야 할 일:** GitHub Pages 켜기, itch.io API 키를 저장소 비밀 값(Secret)으로 등록.

### 작업 9: itch.io 임베드에서 턴 예산 확인
- 사용자의 itch 계정으로 비공개 페이지에 올린 뒤 측정합니다. 목표에 못 미치면 작업 2로 돌아갑니다.

작업마다 하던 리뷰는 생략하고 끝에 전체 리뷰를 한 번 합니다(사용자 선호).

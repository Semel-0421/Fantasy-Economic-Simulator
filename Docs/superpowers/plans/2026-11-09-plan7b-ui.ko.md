# Plan 7B: UI·연출 작업 — 구현 계획 (한국어본)

> 원문: `2026-11-09-plan7b-ui.md`(영어, 에이전트용). 역할·규칙: `AGENTS.md`, `Docs/superpowers/agent-rules.md`. Claude가 계획·검토, Codex가 구현(작업마다 커밋 1개, `git commit -- <경로>`), Copilot이 커밋 묶음과 푸시 전에 검사.

**목표:** 동작은 하지만 밋밋한 웹 UI를 데스크톱과 360 px 휴대폰에서 읽기 쉬운, 심사 수준의 2D 픽셀아트 전략 게임 화면으로 만든다. SpriteCook·ElevenLabs 자산이 도착하는 대로 받을 준비를 하고, 엔진은 건드리지 않는다.

**스펙:** `docs/superpowers/specs/2026-11-04-rust-web-port-design.md` 5장(5.1-5.6), 8장, 9장. Plan 7A(자산 목록, `web/public/assets/README.md`).

## 결정 사항 (사용자, 2026-11-09)
- **분위기: "길드 야간".** 어두운 나무틀(`#2B2118`, `#6B5135`, `#A67C52`) 안에 양피지 카드(`#F3E9D2`, `#E4D4AE`). 금화와 유일한 주요 버튼은 금색 `#B07716`, 바다 `#2F5D62`/`#3D7EA6`, 위험 `#8C2F1F`. 자산 12색 팔레트만 쓰고, 어두운 배경 위 금화 글자용 밝은 금색(`#F3C14A`) 하나와 대비 검사상 필요할 때만 흰색을 더한다.
- **글꼴:** 제목·버튼·금화·주차는 픽셀 글꼴(Pixelify Sans), 본문·표·대화상자는 읽기 쉬운 글꼴(Atkinson Hyperlegible), 금화 숫자는 모두 고정폭 숫자. 둘 다 OFL, npm(`@fontsource/*`)으로 게임에 포함하며 실행 중 네트워크로 불러오지 않는다.
- **휴대폰(360 px):** 위 막대(금화, 주차) → 지도 → 아래 탭 시트(목표, 시장, 화물, 더보기), "다음 주" 버튼은 항상 아래에 보인다.
- **성장 연출:** 그 주의 수익 크기에 비례해 0.8-2.0초, 한 주에 한 번(묶음), 클릭·키로 건너뛰기, 동작 줄이기 설정이면 연출 없음.

## 감사 결과 (Claude, 2026-11-09, 개발 빌드, 시나리오 1, 1280x800·360x740)
1. 지도 라벨: 모든 지명을 모든 확대 단계에서 그려 전체 지도가 검은 덩어리로 보인다(`web/src/map/map.ts` `drawBase`). 최우선.
2. 휴대폰에서 시나리오 목표가 지도와 이동 카드 아래에 있어 스크롤하지 않으면 목표가 안 보인다.
3. HUD에 위계가 없다: 금화·날짜·다음 주가 같은 크기 상자, 모든 글자가 Georgia 하나, 0.75 rem 대문자+투명도 라벨은 양피지 위 대비 4.5:1 미만.
4. 라이선스 선택 목록(`ui/finance.ts` `licencePanel`)이 등급별 상품을 모두 나열: 전체 규모 세계에서 약 4,000개.
5. 소개 대화상자 외에 첫 실행 안내가 없고, 글꼴·PixiJS·생성 자산에 대한 크레딧·라이선스 고지(스펙 8장 공개 의무)가 없다.
6. 대화상자: Esc 없음, 닫은 뒤 초점 복귀 없음. 결과 화면은 평범한 표, 메뉴에 시각적 정체성이 없다.
7. 설정의 음량 슬라이더는 있지만 소리는 아직 합성 임시음(`audio/sfx.ts`).

## 공통 제약
- **엔진 변경 없음.** `engine/` 아래 파일은 바꾸지 않으므로 패리티·턴 벤치는 영향이 없다(각 보고서에 "엔진 변경 없음"으로 적고 실행 생략). 엔진 데이터가 필요해지면 멈추고 Claude에게 묻는다.
- 실행 중 네트워크 호출은 게임 자체 파일(같은 출처, README의 상대 경로)만. CDN 글꼴·분석 도구 금지.
- 턴 속도: UI가 턴 안에 일을 더하지 않는다. 지도 다시 그리기는 Worker 밖 메인 스레드에서만, 기존 메인 스레드 응답성 검사와 `npm run smoke`는 계속 통과.
- 자산은 아직 없다. 모든 자산 사용에 완성돼 보이는 대체(벡터·CSS)가 있고, 실제로 있는 파일만 요청한다(404 소음 없음).
- 플레이어가 읽는 글은 영어, 버튼·제목은 문장형 대소문자, 이모지 아이콘 금지.
- 접근성 기준: WCAG AA 대비(글자 4.5:1, 큰 글자·UI 경계 3:1), 보이는 초점, 지도 끌기 외 모든 동작 키보드 가능, 터치 영역 44 px 이상, `prefers-reduced-motion` 준수, 360 px에서 가로 스크롤 없음.
- 작업별 검사(`web/`): `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`. 작업 3·4·5·10은 `npm run smoke`도. Codex 모델 gpt-6.1-sol, 노력 수준은 작업별 표기.
- 파일 길이 제한 준수, 새 UI 모듈은 작고 한 가지 일만 한다.

### 작업 1: 디자인 토큰과 글꼴 (Codex, gpt-6.1-sol, medium)
- `web/src/ui/tokens.css`: 기본 색(위 팔레트), 의미 토큰(틀 배경, 카드 배경, 카드 위 글자, 틀 위 글자, 금화, 주요 버튼, 위험, 초점), 간격(4/8/12/16/24/32 px), 모서리(0 또는 2 px, 픽셀 느낌), 2 px 픽셀 테두리, 글자 크기(12/14/16/20/24/32 px, 본문 16 px·줄간격 1.5), 동작 시간(빠름 120 ms, 기본 200 ms)과 동작 줄이기 대체.
- 글꼴: `@fontsource/pixelify-sans`, `@fontsource/atkinson-hyperlegible`(정확한 버전, `dependencies`, Vite가 woff2를 빌드에 포함). `font-display: swap`, 대체 `system-ui`, 숫자는 `tabular-nums`.
- `styles.css`는 토큰만 사용(`tokens.css` 밖 원시 hex 금지). 이를 검사하는 단위 테스트.
- 대비 테스트: 의미 토큰의 글자/배경 쌍마다 WCAG 대비를 계산해 4.5 이상(큰 글자·UI 경계는 3 이상) 확인.

### 작업 2: 자산 불러오기와 우아한 대체 (Codex, gpt-6.1-sol, high)
- `web/scripts/prepare.mjs`가 `public/assets/` 아래 실제 있는 파일 목록 `web/public/assets/present.json`을 만든다(git 제외, 매 실행 생성). 서비스 워커는 있는 파일만 미리 저장.
- `web/src/assets/manifest.ts`: README의 id→경로 표 52행 전체와 상품 키 규칙(이름 있는 29개, `g1_0`→밀, `g6_0`→철 도구, `g19_0`→지역 특산품, 나머지 합성 상품→무역 상자, 등급 접미어 제거). README 표와 일치하는지, 기본 키 1,029개가 모두 연결되는지 단위 테스트.
- `web/src/assets/loader.ts`: `present.json`에 있는 id만 불러온다. 그림은 Pixi `Assets`, 최근접 보간·정수 배율. 소리는 OGG를 Web Audio로 해독. 실패하면 조용히 대체(요약 `console.info` 한 줄, 오류 없음).
- 대체: 지형→현재 벡터 경로, 마을→등급별 벡터 모양(작업 5), 상품→상품 첫 글자와 분류 색의 24 px 픽셀 칩, 테두리→CSS 픽셀 테두리, 음악→없음, 효과음→현재 합성음.
- 소리: `audio/sfx.ts`를 `audio/sound.ts`로(`play('coin'|'button'|'event'|'results')`). 첫 사용자 동작 뒤 음악 시작, 메뉴 음량 설정 적용(마스터 게인), HUD에 음소거 버튼. 메뉴에서는 메뉴 음악, 게임 중에는 게임 음악 반복.
- 테스트: manifest/README 일치, `present.json`이 비면 아무것도 요청하지 않음, 가짜 목록이면 그 경로만 요청, 음량 0이면 무음.

### 작업 3: 데스크톱 게임 틀과 HUD (Codex, gpt-6.1-sol, high)
- 900 px 이상: 어두운 틀, 위 막대 왼쪽부터 금화(픽셀 글꼴, 금색, 가장 큰 요소), 주차(시나리오는 `Week 3 / 20`, 자유 모드는 달력 날짜), 상태 칩(X로 이동 중, N주 도착), 빈 공간, 음소거, 저장(자유 모드), 메뉴. 위 막대 오른쪽에 큰 "Next week" 버튼(유일한 금색 주요 버튼).
- 본문: 왼쪽 지도(폭 60% 이상), 오른쪽 탭 패널 — **Goal**(시나리오 패널, 자유 모드에선 숨김), **Market**, **Cargo**, **Finance**(거래소·채권·라이선스·지갑), **Log**. 탭은 WAI-ARIA tablist(화살표, Home/End). 시나리오는 Goal, 자유 모드는 Market 탭으로 시작.
- 이동 조작은 지도 위 카드(지도 왼쪽 아래)로: 현재 마을, 선택한 마을, 경로 목록, 호위·보험, Travel 버튼.

### 작업 4: 휴대폰 화면 360-899 px (Codex, gpt-6.1-sol, high)
- 위 막대: 금화와 주차만(메뉴는 `aria-label` 있는 아이콘 버튼). 지도는 위 막대와 시트 사이를 채움(최소 45 vh).
- 아래 시트: 작업 3과 같은 탭 중 Goal, Market, Cargo, More(More = Finance, Log, 이동 옵션, 저장, 메뉴). 시트 높이는 접힘(탭만)·절반·전체, 활성 탭을 다시 누르거나 손잡이로 변경(끌기는 선택, 탭은 필수). "Next week"는 탭 막대 아래 전체 폭 버튼으로 항상 보임, `env(safe-area-inset-bottom)` 여백.

- 360 px에서 가로 스크롤 없음. 시장 표는 카드 안에서 스크롤, 첫 열 고정.
- 테스트: 360x740에서 소개 뒤 스크롤 없이 Goal이 보임, 모든 탭에서 Next week가 보임, 문서 `scrollWidth <= 360`.

### 작업 5: 지도 가독성 (Codex, gpt-6.1-sol, high)
- 확대 단계별 라벨: 전체 보기에서는 대륙·국가 이름만, 일정 확대부터 지역 이름, 마을 이름은 충분히 확대했을 때나 플레이어 마을·그 경로 이웃·선택 마을·시나리오 목표 마을일 때만. 라벨은 본문 글꼴에 2 px 어두운 외곽선.
- 겹침 처리: 화면 좌표에서 우선순위(플레이어 > 선택 > 목표 > 등급순)로 놓으며 겹치는 라벨은 숨김. 매 프레임이 아니라 확대가 끝날 때 다시 계산.
- 마을: 로더의 `WorldLevel`별 그림, 대체는 크기뿐 아니라 모양으로 구분(마을 점, 도시 테두리 사각형, 지역·국가·대륙 문장). 플레이어 표식 그림 또는 금색 마름모, 선택 마을 고리, 지형별 경로 색과 바닷길 점선.
- 지도 조작: 지도 모서리에 확대·축소·전체 보기 버튼(44 px). 지도에 초점이 있을 때 `+`/`-`/`0` 키. 캔버스에 `aria-label`, 경로 목록이 키보드 이동 경로로 남음.
- 성능: 전체 규모 세계에서 라벨 계산 4 ms 이하(테스트로 측정해 보고서에 기록).
- 테스트: 전체 보기에서 보이는 라벨 40개 이하, 보이는 라벨끼리 겹치지 않음, 플레이어 마을 라벨은 항상 보임, 기존 테스트용 `screenOf` 그대로.
- **커밋.**

### 작업 6: 메뉴, 대화상자, 결과 화면 (Codex, gpt-6.1-sol, medium)
- 메뉴: 어두운 틀 위 픽셀 글꼴 제목, 시나리오 카드 3개(번호, 제목, 한 줄 소개, 약 30분, 시나리오 1에 "Recommended first") 다음 Free mode, Continue, 저장, 설정(음량, 음악 켜기/끄기, 동작 줄이기는 시스템 설정 따름), Credits.
- 대화상자: 어둡게 한 틀 위 양피지 카드. 초점이 대화상자로 이동, Tab은 안에서만 돌고, Esc나 버튼으로 닫으면 원래 요소로 초점 복귀. 사건 대화상자에 `event` 소리.
- 결과: 장부 카드 — 수입, 비용(위험 색), 점수인 순이익을 가장 큰 금화 스타일로, 목표 대비 줄(`Target 1,000 · You 2,140`), 목표 달성은 색만이 아닌 체크 모양으로. 버튼 "Next scenario"(주요)와 "Main menu". `results` 소리 한 번.
- Credits 화면(메뉴에서): 글꼴(이름, OFL), PixiJS(MIT), 스펙 8장·`Docs/assets/asset-log.md`의 자산 도구와 공개 문구(그림 SpriteCook, 소리 ElevenLabs, 영어 문장 초안 Claude), "실행 중 AI·네트워크 호출 없음".
- 테스트: 대화상자 초점 가두기와 Esc, 결과에 순이익 점수와 목표 표시, Credits가 포함된 모든 글꼴·라이브러리와 라이선스를 나열(`package.json` 의존성 기준).
- **커밋.**

### 작업 7: 성장 연출 시간 (Codex, gpt-6.1-sol, medium)
- `growthDuration(total, coinsBefore)`: 800 ms + 지갑 대비 수익 크기(로그 척도)로 최대 1,200 ms, 800-2,000 ms로 제한. `countedValue`가 이 시간을 받음. 한 주 한 번 묶음, 포인터/키로 건너뛰기, 뒤 게임 입력 차단은 그대로.
- 모양: 금화 블록이 1.25배로 커지고(transform만) 픽셀 금색 테두리, 수익 목록을 툴팁과 `aria-live="polite"` 줄로 알리는 "+N" 표시, 시작할 때 동전 소리. 동작 줄이기면 숫자를 바로 바꾸고 "+N"만 1.5초 표시.
- 스펙 5.2: 배당(시나리오 2)과 해외 판매(시나리오 3)도 같은 연출. 수익 목록이 이를 포함하는지 확인.
- 테스트: 시간 범위와 단조 증가, 동작 줄이기 경로는 즉시 값 설정, 건너뛰면 정확한 합계로 끝남.
- **커밋.**

### 작업 8: 첫 실행 안내 (문구는 Claude, 구현은 Codex, medium)
- 시나리오 1 첫 실행만(`localStorage`의 `fes-guide-s1-done`, try/catch로 보호): 소개 대화상자 뒤 4단계 안내 — 1 금화("Your purse"), 2 시장 탭("Buy the cheap grain here"), 3 지도의 목표 마을과 이동 카드("Choose where to sell"), 4 Next week("End your week; merchants move"). 단계마다 해당 요소를 가리키고 Next/Skip, Esc는 건너뛰기, 자기 오버레이 외에는 게임을 막지 않음.
- 설정에 "Show the guide again". 자유 모드는 첫 시작에 닫을 수 있는 한 줄 안내.
- 최종 영어 문구는 Claude가 작업 지시에 넣고 Codex는 문구를 만들지 않는다.
- 테스트: 안내는 한 번만, 건너뛰면 기록, 저장소가 막혀도 플레이 가능(안내 표시, 예외 없음).
- **커밋.**

### 작업 9: 라이선스 목록 정리 (Codex, gpt-6.1-sol, medium)
- 라이선스 선택은 **기본 상품만**(등급 없이 기본 키당 하나): 현재 시나리오가 요구하는 상품 먼저, 다음은 불러온 `goods.csv`에서 `requires_license=1`인 상품, 그다음 "Show all goods"를 켜면 나머지를 이름순으로. 전체 규모 데이터에서도 짧은 목록이 된다(현재 약 4,000개).
- 보유 라이선스는 상품, 국가, "expires week N" 표시. 무역 라이선스는 범위(국가 간/대륙 간)와 짧은 설명.
- 데이터는 웹이 이미 불러오는 파일에서. 시나리오의 라이선스 상품이 UI에 없다면 UI가 이미 받는 RON/JSON에서 읽거나 멈추고 Claude에게 묻는다(엔진 변경 금지).
- 테스트: 전체 규모 상품으로 "Show all" 전 목록 50개 이하, 시나리오 3에서 `g19_0`이 첫 번째, 보유 라이선스에 국가와 만료 표시.
- **커밋.**

### 작업 10: 설치된 Edge에서 UI 테스트 (Codex, gpt-6.1-sol, medium)
- `web/tests/e2e/ui.test.ts`(운영 빌드에 Playwright, `BROWSER_CHANNEL` 기본 `msedge`, CI는 smoke처럼 `chromium`): 1280x800과 360x740에서 메뉴, 시나리오 1 시작(소개, 안내), 시장 구매, Next week, 성장 연출, 대화상자, 결과(테스트에 짧은 경로가 있으면 그것, 없으면 고정 결과표로 그린 화면), Credits.
- 화면마다: 가로 넘침 없음, 모든 버튼·링크 44x44 px 이상, Tab 뒤 초점 보임, 콘솔 오류 없음, `reducedMotion: 'reduce'`면 금화 숫자가 즉시 최종값, axe-core(`@axe-core/playwright`, 개발용)에서 serious·critical 위반 없음.
- 화면·크기별 스크린샷을 `web/test-results/ui/`(git 제외)에 저장해 Claude가 검토.
- `npm run test:ui` 추가, CI는 `chromium`으로 실행.
- **커밋.**

### 작업 11: 검토, 검사, 푸시 (Claude, Copilot, 사용자)
- Claude가 작업 보고서와 작업 10 스크린샷을 이 계획과 감사 목록에 대조해 검토하고, 부족한 점은 Codex에게 돌려보낸다.
- Copilot이 푸시 전 전체 검사(웹 검사, smoke, test:ui. 엔진 변경 없음 → 같은 엔진 트리의 기록된 결과 재사용을 보고서에 명시).
- 푸시 전에 Claude가 사용자에게 묻는다. 푸시 뒤 Pages 배포 확인.

## 검토 중점
- 엔진 파일, 턴 결과, 미리보기 일치를 바꾸는 변경(엔진을 안 건드리므로 없어야 함).
- 같은 출처 게임 파일 외의 실행 중 네트워크 요청(글꼴, CDN, 분석).
- 없는 자산 경로가 오류를 남기거나, 깨진 그림을 보이거나, 플레이를 막는 경우.
- 대비·초점·터치 영역 실패, 동작 줄이기 미준수.
- 휴대폰: Goal이나 Next week가 가려짐, 가로 스크롤.
- 지도 라벨 계산이 느리거나 라벨이 겹침.
- Claude가 준 문구 대신 Codex가 지어낸 문구.

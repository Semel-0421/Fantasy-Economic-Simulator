# Plan 7B: UI and Presentation Pass — Implementation Plan

> **For agents:** Roles and rules: `AGENTS.md`, `Docs/superpowers/agent-rules.md`. Claude plans and reviews, Codex builds (one commit per task, `git commit -- <paths>`), Copilot gates before every commit batch and push. Korean copy for the user: `2026-11-09-plan7b-ui.ko.md`.

**Goal:** Turn the working but plain web UI into a readable, judged-quality 2D pixel-art strategy game screen on desktop and 360 px phones, ready to take the SpriteCook and ElevenLabs assets as they arrive, without touching the engine.

**Spec:** `docs/superpowers/specs/2026-11-04-rust-web-port-design.md` sections 5 (5.1-5.6), 8, 9. Plan 7A (asset lists, `web/public/assets/README.md`).

## Decisions (user, 2026-11-09)
- **Look: "Guild night".** Dark wood frame (`#2B2118`, `#6B5135`, `#A67C52`) around parchment cards (`#F3E9D2`, `#E4D4AE`); gold `#B07716` for coins and the one primary action; sea `#2F5D62`/`#3D7EA6`; danger `#8C2F1F`. Only the 12-colour asset palette of `Docs/assets/art-list.md`, plus one bright gold for coin text on dark (`#F3C14A`) and pure white only if a contrast check needs it.
- **Type:** a pixel face for titles, buttons, coins and week (Pixelify Sans); a legible face for body, tables and dialogs (Atkinson Hyperlegible); tabular numbers everywhere coins appear. Both OFL, bundled from npm (`@fontsource/*`), never loaded from the network at runtime.
- **Phone (360 px):** top bar (coins, week), map, bottom tab sheet (Goal, Market, Cargo, More), "Next week" always visible at the bottom.
- **Growth presentation:** count-up length scales with the week's gain, 0.8-2.0 s, one presentation per week, skip by click/key, none with reduced motion.

## Audit (Claude, 2026-11-09, dev build, scenario 1, 1280x800 and 360x740)
1. Map labels: every node name is drawn at every zoom, so the world view is an unreadable black mass (`web/src/map/map.ts` `drawBase`). Highest priority.
2. On a phone the scenario objectives sit below the map and travel card; the player cannot see the goal without scrolling.
3. HUD has no hierarchy: coins, date and Next week are equal boxes; one serif face (Georgia) for everything; labels in uppercase at 0.75 rem with opacity (contrast below 4.5:1 on parchment).
4. Licence select (`ui/finance.ts` `licencePanel`) lists every graded good: about 4,000 options in the full-scale world.
5. No first-run guidance beyond the intro dialog; no credits or licence notice for fonts, PixiJS and generated assets (spec 8 disclosure).
6. Dialog: no Escape, no focus return; results screen is a plain table; menu has no visual identity.
7. Settings volume slider exists but sound is still the synth placeholder (`audio/sfx.ts`).

## Global Constraints
- **Engine untouched.** No file under `engine/` changes; parity and the turn bench are therefore unaffected (state "engine untouched" in each report instead of running them). If a task finds it needs engine data, stop and ask Claude.
- No runtime network calls except loading the game's own files (same origin, relative URLs per `web/public/assets/README.md`). No CDN fonts, no analytics.
- Turn speed: the UI never adds work inside a turn. Map redraws stay on the main thread outside the Worker; the existing main-thread responsiveness check and `npm run smoke` stay green.
- Assets are not generated yet. Every asset use has a fallback that looks finished (vector or CSS), and the UI requests only files that exist (no 404 noise).
- Text the player reads is English; sentence case for buttons and headings; no emoji as icons.
- Accessibility floor: WCAG AA contrast (4.5:1 text, 3:1 large text and UI edges), visible focus, keyboard play for every action except map panning, touch targets ≥ 44 px, `prefers-reduced-motion` honoured, no horizontal scroll at 360 px.
- Gates per task (in `web/`): `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`; Tasks 3, 4, 5 and 10 also `npm run smoke`. Codex model: gpt-6.1-sol; effort as listed.
- Files stay under the repo's length limits; new UI modules are small and single-purpose.

### Task 1: Design tokens and fonts (Codex, gpt-6.1-sol, medium)
- `web/src/ui/tokens.css`: primitive colours (the palette above), semantic tokens (`--surface-frame`, `--surface-card`, `--text-on-card`, `--text-on-frame`, `--accent-coin`, `--action-primary`, `--danger`, `--focus`), spacing scale (4/8/12/16/24/32 px), radii (0 or 2 px: pixel look), border widths (2 px pixel borders via `box-shadow` steps), type scale (12/14/16/20/24/32 px; body 16 px, line-height 1.5), motion durations (`--dur-fast` 120 ms, `--dur-base` 200 ms) with reduced-motion overrides.
- Fonts: add `@fontsource/pixelify-sans` and `@fontsource/atkinson-hyperlegible` (exact versions, as `dependencies`; Vite bundles the woff2 into the build). `font-display: swap`; fallback stack `system-ui`. Numbers: `font-variant-numeric: tabular-nums`.
- `styles.css` uses only tokens (no raw hex outside `tokens.css`); a unit test greps `src/ui/*.css` and `src/**/*.ts` for raw `#hex` colours outside `tokens.css` and the Pixi colour module.
- Contrast test: a small table of the semantic text/background pairs with computed WCAG ratios asserted ≥ 4.5 (≥ 3 for large text and UI edges).
- **Commit.**

### Task 2: Asset loading with graceful fallback (Codex, gpt-6.1-sol, high)
- `web/scripts/prepare.mjs` writes `web/public/assets/present.json` (ignored by git, built each run) listing the files that exist under `public/assets/` (excluding `.gitkeep`, `README.md`). The build includes it; the service worker precaches only existing files.
- `web/src/assets/manifest.ts`: the id → path table of `web/public/assets/README.md` (all 52 rows), the goods key rule (29 named keys, `g1_0` → wheat, `g6_0` → iron tools, `g19_0` → regional specialty, other synthetic → trade crate; grade suffix stripped). A unit test checks every id, path and size against the README table and that all 1,029 base keys map.
- `web/src/assets/loader.ts`: loads only ids in `present.json`; images via Pixi `Assets` with `scaleMode: 'nearest'` and integer scaling; audio decoded through Web Audio from OGG. Each failure falls back silently (one `console.info` summary, no errors).
- Fallbacks: terrain → current vector routes; towns → levelled vector shapes (Task 5); goods → a 24 px pixel chip with the good's initial and category colour; frame → CSS pixel border; music → none; sfx → current synth sounds.
- Audio: `audio/sfx.ts` becomes `audio/sound.ts` with `play('coin'|'button'|'event'|'results')`, music start after the first user gesture, the menu volume setting applied (master gain), a mute toggle in the HUD. Music loops: menu loop on the menu, game loop in play.
- Tests: manifest/README equality; loader with an empty `present.json` requests nothing; with a fake present list it requests exactly those paths; volume 0 plays nothing.
- **Commit.**

### Task 3: Desktop game shell and HUD (Codex, gpt-6.1-sol, high)
- Layout ≥ 900 px: dark frame; top bar left to right: coins (pixel face, gold, largest element), week (`Week 3 / 20` in scenarios, calendar date in free mode), status chip (travelling to X, arrives week N), spacer, mute, save (free mode), menu; big "Next week" button on the right of the top bar (the only gold primary action).
- Main: map (left, ≥ 60 % width), right panel with tabs: **Goal** (scenario panel; hidden in free mode), **Market**, **Cargo**, **Finance** (exchange, bonds, licences, purse), **Log**. Tabs are a WAI-ARIA tablist (arrow keys, Home/End). The scenario opens on Goal; free mode on Market.
- Travel controls move into a map overlay card (bottom-left of the map): current town, selected town, route list, guards/insurance, Travel button.
- Turn in progress: Next week shows "Merchants moving… Ns" with the progress bar (static with reduced motion); the panels stay readable but inert.
- Existing element ids used by tests (`#coins`, `#date`, `#next`, `#log`, `#qty`, `#licence-good`, …) are kept so the current UI tests and smoke keep working; any rename updates its tests in the same commit.
- Tests: tab keyboard behaviour; scenario opens on Goal; free mode hides Goal; current flow/play/trade tests green.
- **Commit.**

### Task 4: Phone layout, 360-899 px (Codex, gpt-6.1-sol, high)
- Top bar: coins and week only (menu as an icon button with `aria-label`). Map fills the space between top bar and sheet (min 45 vh).
- Bottom sheet: the same tabs as Task 3 with Goal, Market, Cargo, More (More = Finance, Log, Travel options, Save, Menu); the sheet has collapsed (tab bar only), half and full heights, changed by tapping the active tab or a drag handle (drag optional; tap must work). "Next week" is a full-width button under the tab bar, always visible; `env(safe-area-inset-bottom)` padding.
- Travel overlay becomes a compact card above the sheet when a town is selected.
- No horizontal scroll at 360 px; tables in Market scroll inside their card with a sticky first column.
- Tests: at 360x740 Goal is visible without scrolling after the intro; Next week visible on every tab; document `scrollWidth <= 360`.
- **Commit.**

### Task 5: Map readability (Codex, gpt-6.1-sol, high)
- Level-of-detail labels: at the fitted world view show only continent and nation names; region names from a zoom threshold; town names only when zoomed in enough or for the player's town, its route neighbours, the selected town and scenario target towns. Labels use the body face with a dark 2 px outline (Pixi text stroke) on the map colours.
- Collision: a greedy screen-space pass (priority: player > selected > targets > by level) hides labels that overlap a placed one; recomputed on zoom end, not every frame.
- Towns: sprites by `WorldLevel` from the loader, fallback vector shapes that differ by shape as well as size (village dot, city square with border, region/nation/continent emblems); player marker sprite or gold diamond; selected town ring; route colour by terrain with a dashed style for sea routes.
- Map controls: zoom in/out and "fit" buttons (44 px) in the map corner; keyboard: `+`/`-`/`0` when the map has focus; the map canvas gets `aria-label` and the route list stays the keyboard path for travel.
- Performance: label pass ≤ 4 ms on the full-scale world (measured in a test with the full-scale map data, recorded in the report).
- Tests: at the fitted view the visible label count ≤ 40 and no two visible label boxes overlap; player town label always visible; `screenOf` unchanged for existing tests.
- **Commit.**

### Task 6: Menu, dialogs and results screen (Codex, gpt-6.1-sol, medium)
- Menu: title in the pixel face on the dark frame; three scenario cards (number, title, one-line pitch, ~30 min, "Recommended first" on scenario 1) then Free mode, Continue, Saves, Settings (volume, music on/off, reduced motion follows the system), Credits.
- Dialogs: parchment card on a dimmed frame; focus moves to the dialog, Tab stays inside, Escape or the button closes news dialogs, focus returns to the element that had it; event dialogs play `event` sound.
- Results: a ledger card — revenue, costs (danger colour), net profit as the score in the largest coin style, target and "1.3x" style comparison line (`Target 1,000 · You 2,140`), objectives with check marks (shape, not colour only); buttons "Next scenario" (primary) and "Main menu"; `results` sound once.
- Credits screen (from the menu): fonts (names, OFL), PixiJS (MIT), the asset tools and disclosure text from spec 8 / `Docs/assets/asset-log.md` (art: SpriteCook, sound: ElevenLabs, English text drafted with Claude), "No AI or network calls at runtime".
- Tests: dialog focus trap and Escape; results shows net profit as score and target; credits lists every bundled font and library with its licence (test reads `package.json` dependencies).
- **Commit.**

### Task 7: Growth presentation timing (Codex, gpt-6.1-sol, medium)
- `growthDuration(total, coinsBefore)`: 800 ms + up to 1,200 ms by the gain's size relative to the purse (log scale), clamped 800-2,000 ms; `countedValue` takes the duration. Same batching (one per week), same skip by pointer/key, same inert game behind it.
- Visual: coins block scales up 1.25x with a pixel gold frame (transform only), a "+N" tag that lists the gains in a tooltip and in an `aria-live="polite"` line; coin sound at start; with reduced motion the number is set at once and only the "+N" tag shows for 1.5 s.
- Spec 5.2: dividends (scenario 2) and abroad sales (scenario 3) use the same presentation; check the gains list covers them.
- Tests: duration bounds and monotonicity; reduced motion path sets the value at once; skip ends at the exact total.
- **Commit.**

### Task 8: First-run guidance (Claude writes text, Codex builds; medium)

Each step points at the element, has Next/Skip, Escape skips; no step blocks the game beyond its own overlay.

- Claude provides the final English strings in the task brief; Codex does not invent copy.
- Tests: guide shows once, skip stores the flag, blocked storage still allows play (guide shows, nothing throws).
- **Commit.**

### Task 9: Licence list cleanup (Codex, gpt-6.1-sol, medium)
- The licence select offers **base goods only** (one entry per base key, no grades): first the goods the current scenario licenses (`licensed` in the scenario view or data), then goods with `requires_license=1` in the loaded `goods.csv`, then a "Show all goods" toggle that reveals the rest sorted by name. With the full-scale data this is a short list, not ~4,000 options.
- Held licences show good, nation and "expires week N"; trade licences show their scope (international / intercontinental) with a short explanation line.
- Data comes from files the web already loads; if a scenario's licensed goods are not exposed to the UI, read them from the served RON/JSON the UI already fetches, or stop and ask Claude (no engine change).
- Tests: full-scale goods list → select length ≤ 50 before "Show all"; scenario 3 shows `g19_0` first; held licences render nation and expiry.
- **Commit.**

## Review Focus
- Anything that changes engine files, a turn result or the preview equality (should be impossible: engine untouched).
- A runtime network request other than same-origin game files (fonts, CDN, analytics).
- A missing-asset path that logs errors, shows broken images or blocks play.
- Contrast, focus and touch-target failures; reduced motion not honoured.
- Phone: Goal or Next week hidden, horizontal scroll.
- Map label pass slow or overlapping labels.
- Copy that Codex invented instead of the strings Claude supplied.

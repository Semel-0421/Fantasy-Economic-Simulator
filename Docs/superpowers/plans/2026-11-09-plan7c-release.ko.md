# Plan 7C: 이름, 자산 적용, 심사용 릴리스 — 구현 계획 (한국어본)

> 원문: `2026-11-09-plan7c-release.md`. 역할·규칙: `AGENTS.md`, `Docs/superpowers/agent-rules.md`. Claude가 계획·플레이어용 이름과 문구·검토, Codex가 구현(작업마다 커밋 1개, `git commit -- <경로>`), Copilot이 푸시 전 검사, 모든 푸시와 계정 작업은 사용자 승인·사용자 직접.

**목표:** 로드맵의 Plan 7(자산, 다듬기, 제출)을 마무리한다. 세계가 키 문자열이 아니라 판타지 세계처럼 읽히게 하고, 사용자가 SpriteCook/ElevenLabs 파일을 넘기면 적용하며, 실제 빌드로 게임플레이 영상과 썸네일을 만들고, 2026-12-24 전에 고정된 심사용 릴리스를 낸다.

**스펙:** 3장(대회 조건), 5장, 8장, 9.1장. 로드맵 7행. Plan 7A, 7B.

## 이 작업들을 고른 이유 (Claude, 2026-11-09)
- 전체 규모 세계의 지명이 비어 있고(`map_nodes.csv` 이름 열 공백), 상품은 `g0_0`~`g19_49`라서 심사위원이 "Buy g19_0 here and sell it in k0n1"을 읽게 된다. 남은 어떤 시각 문제보다 주제·완성도·창의성 점수에 불리하다.
- 전체 지도 보기에서 마을 기호가 빽빽해 라벨과 겹친다(Plan 7B 작업 12의 남은 문제). 사용자가 육각 타일 지도를 골랐고(2026-11-09) 이것이 상자 배치를 대체한다.
- 자산이 아직 없다(`present.json` 비어 있음). 불러오기·대체 화면은 있지만 받은 파일을 규격과 대조하는 검사가 없다.
- 대회는 내려받을 수 있는 게임플레이 영상과 썸네일을 요구하고, 제출하면 작품이 고정된다.

## 공통 제약
- **엔진·데이터 해시 변경 없음.** 이름과 육각 배치는 노드/상품 키로 찾는 UI 층이다. `engine/`, 엔진 고정 데이터, `map_nodes.csv`/`goods.csv`, 저장 바이트는 바꾸지 않는다. 시나리오 RON 문구는 바꿀 수 있다(Plan 7A 규칙): 시나리오별 골든 순이익은 목표의 1.3배 이상, 골든 테스트 모두 통과.
- 표시 이름은 결정적(키의 순수 함수, 실행 중 무작위·네트워크 없음).
- 실행 중 네트워크·AI 호출 없음. 작업별 검사(`web/`): lint, typecheck, test, build, 화면을 건드리면 smoke와 test:ui도. 엔진을 건드릴 일은 없어야 하므로 벤치는 예외 상황에만.
- 사용자만 할 수 있는 일(계정, 자산 생성, itch.io 페이지, 최종 제출)은 한국어 사용자 체크리스트에 올리고 에이전트는 하지 않는다.

### 작업 1: 표시 이름 (이름은 Claude, 구현 Codex, gpt-6.1-sol, medium)

- 노드·상품이 보이는 모든 곳(지도 라벨, 이동, 시장, 화물, 금융, 시나리오 패널, 대화상자, 결과, 기록, 메뉴 소개)에서 표시 이름 사용. 시나리오·사건 문구 안의 키(`k0n0r0c1`, `g19_0`)는 표시할 때 단어 단위로 이름으로 바꾸고, 자연스럽게 읽히도록 Claude가 RON 문구를 고칠 수도 있다.
- 테스트: 시나리오가 언급하는 키마다 직접 지은 이름 존재, 세 시나리오 시작 화면과 결과 화면 고정 데이터에서 보이는 글자에 키 형태(`k0n1`, `g19_0` 등)가 남지 않음(Playwright 글자 검사), 이름이 실행마다 같음(표본 20개 스냅샷).

### 작업 2: 육각 타일 지도 (Codex, gpt-6.1-sol, high) — 사용자 결정 2026-11-09
사용자는 지도를 육각 타일로, 전략 게임의 육각 지도(문명 시리즈)를 참고해 그리기를 원한다. 장르 공통 형식(육각 격자, 영토 경계, 지형 타일, 타일 위 마을)만 쓰고 우리 팔레트와 픽셀 스타일로 그린다. 어떤 게임의 그림·아이콘·배치도 베끼지 않는다.
- **격자:** 꼭짓점이 위인 축 좌표 육각 격자(`web/src/map/hex.ts`: 좌표↔픽셀 변환, 이웃, 육각 직선, 점 아래 육각). 확대 1에서 타일 28x32 px.
- **배치(`web/src/map/hex_layout.ts`, 결정적, UI 전용):** 대륙마다 바다로 나뉜 육지 섬, 그 안에 국가마다 이어진 영토 하나, 그 안에 지역마다 이어진 구역, 도시·마을은 자기 지역 안의 육각 하나씩. 노드 계층과 경로 그래프만으로 배치(무작위 없음, 같으면 노드 id 순)해서 같은 지도 데이터는 항상 같은 그림. 그리기용으로 `layout.ts`의 상자 배치를 대체하고, 키와 `screenOf`·선택 동작은 유지.
- **육각별 지형:** 경로의 육각 직선 위 칸은 그 경로 지형(평지 위 도로, 강, 산길, 바닷길), 나머지 육지는 좌표 해시와 산길까지 거리로 평지·숲·언덕, 그 밖은 바다. 지형은 장식일 뿐이고 이동 시간과 규칙은 계속 엔진 경로에서 나온다.
- **그리기:** 지형 층은 한 번 그려 텍스처로 저장(크기가 바뀔 때만 다시), 국가 경계는 다른 국가 칸 사이 굵은 색 선, 지역 경계는 가는 점선, 도로·바닷길은 칸 중심을 잇는 선, 마을은 자기 칸 위 표식(축소 시 점, 마을 라벨이 보이면 문장·그림), 플레이어·선택·목표 표식은 항상 보임. 라벨은 Plan 7B의 화면 고정 층 그대로.
- **입력:** 누른 칸의 마을, 없으면 한 칸 이내 가장 가까운 마을 선택. 이동·확대·키보드는 지금과 같음.
- **성능:** 전체 규모 세계 배치는 게임 시작 때 한 번 100 ms 이하(측정·기록), 이동·확대는 개발 PC에서 60 fps(프레임 시간 기록), 턴 안의 추가 작업 없음.
- **자산:** 지형 그림을 육각 타일로 바꾼다. `Docs/assets/art-list(.ko).md`, `web/public/assets/README.md`, 목록 코드, 자산 원장을 갱신: `map/terrain/{plains,forest,hills,mountain,water}.png` 육각 타일 28x32 RGBA(육각 밖은 투명), 선택 사항 `map/terrain/road_overlay.png`. 지형 그림을 만들기 전에 사용자(와 pixel-assets 세션)에게 알린다.
- **테스트:** 두 마을이 한 칸을 같이 쓰지 않음, 마을이 자기 지역 구역 안, 국가 영토가 이어져 있음, 두 번 실행해도 같은 배치, 배치 시간 한도, 칸을 누르면 그 마을 선택, 라벨 겹침 테스트 유지, 1280·900·360 스크린샷 검토.
- **커밋.**

### 작업 2b: 시드 기반 지질학적 지도 생성과 지도 성능 (사용자 결정 2026-11-10, 구현 주체는 실행 메모 참고)
사용자는 육각 지도를 난수 시드로, 지질학 규칙을 참고해 현실적으로 생성하고, 지도 최적화 5가지를 모두 적용하며, 확인용 샘플 지도 10장을 원한다.
- **시드와 결정성.** UI 안의 시드 난수 생성기(`web/src/map/gen/rng.ts`). 시나리오는 시나리오별 고정 지도 시드(모든 플레이어가 같은 세계, 스펙 5.2), 자유 모드는 게임 시드. 같은 시드 → 완전히 같은 육각 배열(테스트로 해시 비교), 다른 시드 → 다른 지도. 엔진은 그대로, 지도는 여전히 엔진 노드·경로 그래프 위의 UI 장식.
- **생성 단계(`web/src/map/gen/`), 단계마다 순수 함수와 테스트:**
  1. *판:* 육각 격자에서 시드 기반 다중 시작점 채우기로 지각판 8-14개, 판마다 대륙판/해양판과 이동 방향.
  2. *고도:* 대륙판은 높게, 해양판은 낮게. 대륙-대륙 수렴 경계는 높은 산맥, 해양-대륙 경계는 해안 산맥과 해구, 발산 경계는 열곡·해령. 프랙털 잡음으로 세부, 열점 섬 몇 개.
  3. *침식:* 열·수력 평탄화 몇 단계.
  4. *수계:* 웅덩이 채우기, 가장 낮은 이웃으로 흐름, 유량 누적. 기준 이상인 칸은 바다로 가는 강, 닫힌 분지는 호수.
  5. *기후:* 위도와 고도(기온 감률)로 기온, 위도대별 탁월풍(무역풍·편서풍·극동풍), 바람을 따라 바다에서 오는 습기, 바람받이 사면의 지형성 강수와 산맥 뒤 비그늘.
  6. *생물군계:* 기온 × 습도(휘태커식)와 고도로 결정: 물, 평지, 숲, 언덕, 산, **사막, 설원**(지형 종류 2개 추가. 자산 규격에 선택 사항 `map/terrain/desert.png`, `snow.png`, 색 #E4D4AE, #F3E9D2).
  7. *엔진 그래프에 맞추기:* 데이터의 대륙 수(전체 규모 5개)만큼 육지 덩어리, 그 위에 국가와 지역이 이어진 영토, 마을은 육지에, 도시는 강·해안·평지를 우선. 바닷길은 바다 건너 해안 마을을 잇고, 산길은 가능한 한 높은 지대를 지나게. 경로 일치율(지나는 칸과 경로 지형이 맞는 비율)을 보고하고 70% 이상 유지.
- **성능 최적화(5가지 모두):** (1) 필요할 때만 그리기: 멈춰 있으면 Pixi ticker 정지, 카메라 변경·선택·표식·라벨·상단 움직임(턴 계산 중에만)·크기 변경 때만 그림. 멈춰 있을 때 프레임을 그리지 않는다는 테스트. (2) 안티에일리어싱 끄기. (3) 이동 중 처리는 보이는 라벨(최대 40개)만. (4) GPU 최대 텍스처 크기가 허락하면 지형 텍스처를 2배 해상도로, 아니면 1배. (5) 게임 시작 때 메인 스레드에서 지도를 만들지 않음: 시나리오 지도는 고정 시드로 빌드 때 `web/public/data/maps/<scenario>.json`에 미리 계산(테스트가 다시 만들어 비교), 자유 모드 지도는 Web Worker에서 생성. 전체 규모 생성은 개발 PC에서 300 ms 이하.
- **사용자 확인용 샘플:** `npm run maps:samples`가 시드 10개(시나리오 1-3 시드와 다른 7개)를 실제 렌더러로 `web/capture/maps/seed-<n>.png`(전체 보기, 1600x1000)와 `seed-<n>-debug.png`(판, 고도, 강수, 강 패널)로 그리고 `stats.json`(육지 비율, 지형·생물군계 비율, 강 개수·길이, 호수, 경로 일치율, 생성 시간)을 쓴다. Claude가 검토해 커밋 전에 사용자에게 이미지를 보낸다.
- **테스트:** 시드별 결정성, 작업 2의 불변식(마을마다 다른 칸, 마을은 육지, 국가·지역 영토가 이어짐), 육지 덩어리 5개, 강은 아래로 흘러 바다나 호수에 닿음, 습한 띠의 바람받이 해안 옆에 사막 없음(상식 검사), 멈춰 있을 때 그리는 프레임 0, 배치·생성 시간 한도(CI 여유 방식), 기존 라벨·선택·UI 테스트 유지.
- 사용자가 샘플을 본 뒤 **커밋.**
- **변경 (사용자, 2026-11-10): 원통형 세계.** 지도는 원통처럼 동서가 이어지고 남북은 끝이 있다(전략 게임 세계 지도처럼). 격자·잡음·거리·바람 계산이 동서로 이어지고, 대륙이 이음매에 걸칠 수 있다. 렌더러는 지형을 한 바퀴 폭의 텍스처로 구워 세 장을 나란히 보이고, 카메라를 감아 돌리며, 표식·라벨·문장·상단은 가장 가까운 사본에 그린다. 경로·강·선택은 짧은 쪽으로 돈다.
- **변경 (Claude):** 시나리오 지도도 빌드 때 미리 계산하지 않고 자유 모드처럼 Web Worker에서 만든다. 시드별 결과는 같고 코드 경로가 하나로 유지된다. 자유 모드 저장에는 지도 시드를 함께 저장한다.

### 작업 3: 자산 검사와 적용 경로 (Codex, gpt-6.1-sol, medium)
- `npm run check:assets`(`web/scripts/check-assets.mjs`): `web/public/assets/`에 있는 파일마다 이름·폴더가 목록과 맞는지, PNG 크기 정확, RGBA, 가장자리 반투명 번짐 1 px 이하, 200 KB 이하. OGG는 컨테이너, 48 kHz, 길이가 README 기준 ±10% 이내(Node에서 Ogg/Vorbis 머리 정보 파싱, ffmpeg 불필요). 모르는 파일은 실패. 실패하면 목록과 함께 종료 코드 1.
- `npm run assets:log`: 있는 파일의 자산 원장 행(경로, 크기, sha256)을 출력해 Claude가 `Docs/assets/asset-log.md`에 실제 날짜·증거 경로를 채운다.
- Credits는 파일이 있으면 실제 도구 문구로 자동 전환(Plan 7B 작업 6에 있음, 가짜 목록으로 테스트 추가).
- 테스트: 테스트 안에서 만든 작은 정상·불량 PNG/OGG가 각각 통과·실패.
- **커밋.** 사용자가 파일을 주면: 검사 실행, 이름·크기 문제를 사용자와 정리, 원장 갱신, 화면별 스크린샷, 자산을 경로별로 커밋(파일당 5 MB 이하, 합계 8 MB 예산).

## 검토 중점
- 엔진, 고정 데이터, 데이터 CSV, 저장 바이트 변경.
- 플레이어에게 보이는 키 문자열, 중복되거나 부적절한 생성 이름.
- 결정적이지 않거나, 두 마을을 한 칸에 두거나, 다른 게임의 그림을 베낀 육각 배치.
- 너무 느슨한(잘못된 크기·투명도가 통과) 또는 정상 파일을 막는 자산 검사.
- 실제 턴을 돌리지 않고 결과를 꾸민 촬영 스크립트.
- 제출 뒤 심사 페이지를 바꾸거나 사용자 대신 에이전트가 하는 릴리스 단계.

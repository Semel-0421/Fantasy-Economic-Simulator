# Plan 7D: 언어 옵션 (한국어와 사용자 수 상위 20개 언어) — 구현 계획

> **에이전트용:** 역할과 규칙은 `AGENTS.md`, `Docs/superpowers/agent-rules.md`. Claude는 계획, 번역과 이름 작성, 검토를 맡고, Codex가 구현(작업마다 커밋 하나, `git commit -- <경로>`), Copilot이 푸시 전 검사, 모든 푸시는 사용자 승인. 영어 원본: `2026-11-10-plan7d-korean.md`.

**목표:** 설정에 언어 선택을 추가해, 개발자와 이후 플레이어가 게임 전체를 자기 언어로 플레이할 수 있게 합니다. 메뉴, HUD, 안내, 대화창, 시나리오 텍스트와 목표, 지명과 상품명까지 포함합니다. 기본값과 심사 언어는 영어로 유지합니다.

**사용자 결정 (2026-11-10):** 모든 빌드의 설정 메뉴에 언어 선택; 이름까지 전부 번역; 언어는 한국어와 세계 사용자 수 상위 20개 언어.

## 공통 제약
- **기본은 영어, 자동 감지 안 함.** 첫 방문, 브라우저 초기화, 언어를 지정하지 않은 모든 테스트는 영어로 보입니다. 그래서 심사 빌드는 영어로 플레이됩니다(설계서 3절). 선택은 `localStorage`(`fes-lang`)에 저장합니다.
- **엔진, 데이터, 세이브는 그대로.** `engine/`, 픽스처, `data/scenarios/*.ron`, `map_nodes.csv`/`goods.csv`, 세이브 바이트, 골든 해시를 바꾸지 않습니다. 언어는 UI 층에서만 처리합니다: 엔진은 영어 텍스트와 키를 그대로 보내고, UI가 번역을 찾아 보여 줍니다.
- 모든 언어에서 이름은 결정적입니다(키와 언어만으로 정해짐).
- 실행 중 네트워크·AI 호출 없음. 글꼴은 게임에 포함하고, 그 글꼴이 필요한 언어일 때만 불러옵니다.
- 작업마다 `web/`에서 lint, typecheck, test(`--no-file-parallelism`), build. 화면을 건드리는 작업은 smoke, test:ui도.

## 설계 (Claude)
- **카탈로그.** `web/src/i18n/`: `en.ts`가 원본(`id -> 문자열 | (매개변수) => 문자열`), 언어마다 같은 형태의 파일 하나, 모든 id를 갖췄는지 타입 검사(`satisfies Catalogue`). 함수형 항목으로 언어별 복수형과 어순을 처리합니다(`Intl.PluralRules`). `t(id, params?)`는 시작할 때 정한 언어를 읽습니다. 언어를 바꾸면 저장하고 새로고침합니다(선택기는 메인 메뉴에만 있어 진행 중인 게임을 잃지 않음).
- **언어 목록.** `languages.ts`: 코드, 선택기에 보일 자국어 이름("English", "中文（简体）", "हिन्दी", "Español", "العربية", …, "한국어"), 방향, 글꼴 스택, `Intl` 로캘.
- **시나리오 텍스트.** 엔진은 RON 문자열을 영어로 보냅니다. `scenario/<코드>.ts`는 세 RON 파일의 **영어 원문 문자열을 그대로 키로** 번역을 대응시킵니다. `{qty}`, `{good}`, `{dest}`, `{deadline}`, `{reward}`와 노드·상품 키(`k0n0r0c0`, `g6_0`)는 그대로 두어 `displayText`가 이름을 계속 바꿔 넣습니다. 테스트가 RON 파일을 읽어, 언어마다 빠진 문자열이나 자리표시자·키 불일치가 있으면 실패합니다.
- **이름.** 라틴 문자 언어는 영어 판타지 지명(고유명사)을 그대로 쓰고, 상품명과 일반어(지형, 수식어)만 번역합니다. 라틴이 아닌 문자는 음역합니다: 선별 지명은 직접, 생성 지명은 영어 음절마다 문자별 표(`al`, `bel`, … → `알`, `벨`, …)로 바꿔, 같은 지명이 모든 문자에서 같은 이름으로 읽히게 합니다. 상품은 같은 분류 순서의 언어별 명사 표를 씁니다. 고유성과 금칙어 검사는 언어마다 합니다.
- **숫자와 날짜.** 모든 언어에서 `Intl.NumberFormat(로캘, { numberingSystem: 'latn' })`로 자리 구분을 하되 숫자는 라틴 숫자로 통일합니다(테스트와 스크린샷 비교가 쉬움). 주·연도 표현은 카탈로그에서 가져옵니다.
- **오른쪽→왼쪽.** ar, ur은 `<html dir="rtl">`. 방향이 있는 배치는 CSS 논리 속성(`margin-inline-start`, `inset-inline-end`, `text-align: start`)으로 바꿉니다. 지도 캔버스는 뒤집지 않고, 라벨 글자만 오른쪽→왼쪽으로 씁니다.
- **글꼴.** 영어는 Pixelify Sans(제목)와 Atkinson Hyperlegible(본문)을 유지합니다. 다른 언어는 OFL 라이선스이면서 그 언어 카탈로그가 쓰는 모든 글자를 갖춘 픽셀 글꼴일 때만 제목에 씁니다(글꼴의 문자표를 읽는 테스트로 확인). 아니면 제목과 본문 모두 그 문자의 시스템 글꼴 스택을 씁니다(예: `"Noto Sans Devanagari", "Nirmala UI", "Mangal", sans-serif`). 예상: 라틴·키릴·베트남어는 검사를 통과하면 Pixelify Sans, 한국어·일본어는 통과하면 갈무리11, 한자·아랍·인도계 문자는 시스템 글꼴. 크레딧에 포함한 글꼴과 라이선스를 모두 적습니다. `<html lang>`이 선택을 따릅니다.

### Task 1: i18n 층, 영어 카탈로그, 언어 목록, RTL 기반 (Codex, gpt-6.1-sol, high)
- `web/src/i18n/`(`t`, 언어 상태, `en.ts`, `languages.ts`) 추가. `web/src/main.ts`와 `web/src/ui/*.ts`의 플레이어에게 보이는 문자열을 모두 `en.ts`로 옮김(목록: `.superpowers/sdd/2026-11-09-plan7c-release/strings.md`. 구조용 id, CSS 선택자, 저장 키, 벤치 출력은 그대로). id 목록이 안정되면 바로 `.superpowers/sdd/2026-11-10-plan7d-korean/catalogue-ids.md`에 공개.
- 설정: 라벨 있는 `Language` 선택(21개 자국어 이름), `fes-lang`에 저장, 바꾸면 새로고침. 아직 번역이 끝나지 않은 언어는 id별로 영어로 대체.
- `<html>`의 `dir`/`lang`, 필요한 CSS를 논리 속성으로 변환, `Intl` 숫자 형식.
- 테스트: 영어 화면 변화 없음(기존 UI 테스트가 그대로 통과); 카탈로그 대응 테스트(모든 언어 파일이 `en`의 모든 id를 같은 매개변수 이름으로 갖춤)는 번역 전에는 보고만 하고, 언어를 완료로 표시하면 실패하도록.
- **커밋.**

### Task 2: 한국어 시범 (Claude 작성, Codex 적용, gpt-6.1-sol, low)
- Claude가 `ko.ts`, `scenario/ko.ts`, 한국어 이름 표를 작성. 말투: 안내와 대화는 짧은 해요체, 버튼과 라벨은 명사형. 시범으로 파일 형식과 다른 언어용 검토 기준을 확정합니다.
- Codex가 적용하고 한국어를 완료로 표시, RON 대응 테스트 추가, 게이트 실행. **커밋.**

### Task 3: 나머지 19개 언어 (Claude 작성, Codex 적용, gpt-6.1-sol, low)
- Claude가 `en.ts`와 RON 문자열을 원문으로(뜻 확인용으로 한국어도 참고) 언어별로 번역합니다. 한 언어씩 또는 Claude 하위 에이전트로 병렬 진행하고, 자리표시자·키·길이·말투를 표본 검사합니다. 언어마다 카탈로그, 시나리오 대응, 이름 표.
- Codex가 묶음별로 적용(예: 라틴 문자 언어, 키릴·CJK, 인도계, RTL), 각 언어를 완료로 표시, 게이트 실행. **묶음마다 커밋 하나.**

### Task 4: 모든 언어의 이름과 글꼴 (Codex, gpt-6.1-sol, medium)
- 언어를 받는 `names.ts`(결정적, 고유, 언어별 금칙어 검사), 문자별 음절 표, 상품 명사.
- 글꼴: 검사를 통과한 픽셀 글꼴을 포함해 언어별로 지연 로딩, 나머지는 시스템 스택; 문자표 검사; 크레딧의 라이선스 줄과 기계 번역 안내.
- 테스트: 모든 언어에서 모든 키에 비어 있지 않은 고유한 이름; 영어 이름은 그대로(기존 이름 테스트와 골든 통과).
- **커밋.**

### Task 5: 검토 (Codex, gpt-6.1-sol, medium; Claude 검토)
- `test:ui`를 ko, ar(RTL), ur(RTL, 나스탈리크 높이), ja, zh-Hans, hi(인도계 글자 결합), de와 ru(긴 단어)로 실행: 데스크톱·휴대폰 폭에서 넘침·잘림 없음, 승인한 고유명사 외에 영어 없음, 접근성 검사 통과, 스크린샷은 `web/test-results/ui-<코드>/`.
- 21개 언어 모두 빠른 검사: 언어마다 모든 화면이 그려지고, 빠진 id와 콘솔 오류가 없음.
- Claude가 스크린샷과 실제 문구를 검토하고, 수정은 언어 파일로 되돌려 반영.
- 사용자 체크리스트: 대회가 선택형 추가 언어를 허용하는지 다시 확인(기본은 영어 유지).
- **커밋.**

## 순서와 의존성
1 → 2 → 3 → 4 → 5. id 목록이 공개되면 Task 1 구현 중에 Task 2, 3 문구를 쓸 수 있습니다. Task 4의 이름 표는 Task 2, 3에서 나옵니다.

## 검토 초점
- 영어 출력이 조금이라도 바뀜, 또는 사용자가 고르지 않았는데 다른 언어가 됨.
- 완료된 언어에서 영어로 남은 RON 문자열, 목표, 대화.
- 번역에서 자리표시자나 노드·상품 키가 빠짐.
- 깨진 RTL 배치(뒤집힌 지도, 잘못된 숫자 위치, 잘린 나스탈리크).
- 결정적이지 않거나 중복된 이름; 포함한 글꼴의 빈 네모(글자 없음).
- 쓰지 않는 언어의 글꼴을 불러옴; 네트워크 요청.

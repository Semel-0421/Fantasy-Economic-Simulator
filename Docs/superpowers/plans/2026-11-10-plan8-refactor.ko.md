# 계획 8: 배포 전 리팩토링 — 구현 계획 (한국어판)

> 원본: `2026-11-10-plan8-refactor.md`. 두 문서는 함께 갱신합니다. 기준은 `Docs/GDD/05_Refactoring_Standards.md`(DEC-108)를 따릅니다.

**목표:** 심사용 릴리스 전에 코드 구조를 정리합니다. 동작은 바꾸지 않습니다.
- 웹 코드에도 Rust 엔진과 같은 공개 기준을 자동 검사로 적용합니다.
- 엔진과 웹 양쪽에서 쓰지 않는 코드와 중복 코드를 없앱니다.

**현재 상태 (2026-11-10 조사)**
- Rust 엔진: 기준이 이미 자동 검사됩니다(복잡도 15, 함수 길이, 중첩 깊이, 파일 1,000줄). 예외 처리가 8곳 있습니다.
- 웹: 소스 파일 164개에 복잡도, 길이, 중복, 안 쓰는 코드 기준이 하나도 없습니다. 직접 쓴 파일 중 가장 큰 것은 `main.ts` 366줄, `map/map.ts` 312줄, `ui/finance.ts` 274줄입니다.

## 전체 제약
- **구조만 바꿉니다.** 규칙, 수치, 문구, 화면 배치, 버그 수정은 넣지 않습니다. 작업 중 발견한 버그는 보고서에 적고 여기서는 고치지 않습니다.
- 작업마다 동작이 그대로인지 확인합니다.
  - C# 일치 점검 (새 해시를 기록하지 않습니다)
  - 시나리오 모범 플레이 순이익 (1,359 / 3,657 / 2,263)
  - 웹 테스트 전부 (Edge 화면 테스트 포함)
  - 엔진을 건드린 작업 뒤에는 턴 시간 측정 (최악 1초, 평균 0.7초 미만, 이전과 오차 범위 안)
- 작업마다 커밋 1개입니다. 푸시는 Copilot 점검과 사용자 승인 뒤에만 합니다.
- 예외 처리는 한 줄 이유를 붙이고, 드물게만 둡니다.

---

### 작업 1: 웹 기준을 자동 검사로 적용 (Codex, gpt-6.1-sol, 높은 강도)
- 기준 문서의 한도를 웹 lint 규칙으로 넣습니다.
  - 인지 복잡도 15, 순환 복잡도 25
  - 함수 길이 80줄, 중첩 깊이 3, 매개변수 7개, 파일 1,000줄
- 번역 표처럼 데이터만 있는 파일과 자동 생성 파일은 이유를 적고 제외합니다.
- 위반 목록을 먼저 보고서에 적은 뒤, 함수와 모듈을 나눠서 고칩니다.

### 작업 2: 웹의 안 쓰는 코드와 중복 제거 (Codex, gpt-6.1-sol, 중간 강도)
- 쓰지 않는 파일, 내보내기, 의존 패키지를 도구(knip)로 찾아 지웁니다.
- 중복 코드를 도구(jscpd)로 찾아 공통 함수로 뽑습니다. 기준은 10줄에 걸친 100토큰 이상입니다.
- 두 검사를 npm 명령으로 추가하고, 1분 안에 끝나면 CI에도 넣습니다.

### 작업 3: 엔진 예외, 안 쓰는 코드, 중복 (Codex, gpt-6.1-sol, 높은 강도)
- 예외 처리 8곳을 하나씩 검토합니다. 구조를 바꿔 없애거나, 이유를 적고 남깁니다.
- 쓰지 않는 의존 패키지와 공개 항목을 지웁니다.
- 중복 코드는 턴 시간에 영향을 주는 부분을 건드리지 않는 범위에서만 뽑고, 나머지는 보고합니다.

### 작업 4: 기준 문서와 CI (Codex, gpt-6.1-sol, 낮은 강도)
- 기준 문서에 Rust와 웹 칸을 추가합니다(어떤 도구가 어떤 한도를 검사하는지, 실행 명령). C# 칸은 동결된 기준으로 그대로 둡니다.
- CI가 모든 한도를 검사하는지 확인합니다.

### 작업 5: 검토와 점검 (Claude 검토, Copilot 점검)
- Claude가 보고서 4개를 계획과 대조합니다: 동작 변화가 없는지, 예외에 이유가 있는지, 발견된 버그 목록.
- Copilot이 푸시 전 전체 점검을 하고, 푸시는 사용자에게 먼저 묻습니다.

## 검토 중점
- 결과가 바뀌는 "리팩토링": C# 불일치, 순이익 변화, 화면 테스트 기대값 수정은 작업 실패로 봅니다.
- 자주 도는 함수를 쪼개서 턴 시간이 오차 범위를 넘게 느려지는 경우.
- lint를 통과시키려고 규칙을 끄거나 한도를 올리는 경우.
- 테스트나 워커가 동적으로만 쓰는 코드를 안 쓰는 코드로 잘못 지우는 경우.

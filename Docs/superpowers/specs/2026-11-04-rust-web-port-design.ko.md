# 웹용 Rust 재구축, 크로마 어워드 출품작

**[사용자]**는 사용자가 정한 것, **[Claude]**는 Claude가 정한 것입니다(사용자가 바꿀 수 있음).
표시가 없는 내용은 프로젝트의 현재 상태입니다.

## 1. 의도

이 게임은 Unity(C#, Burst)로 만든 턴제 판타지 경제 시뮬레이션입니다. 시뮬레이션을 Rust로 다시 만들며,
이유는 두 가지입니다 **[사용자]**.

1. **속도.** 목표는 모든 노드와 에이전트를 빠짐없이 계산하면서 웹 빌드에서 한 턴 1초입니다(DEC-110).
   마지막 웹 측정은 목표를 넘었습니다: Chrome, 0~53턴, 평균 1.03초, 최악 1.64초, 54턴 중 19턴이 1초 초과.
   Unity 웹 플레이어는 Burst 잡을 한 스레드로만 돌립니다.
2. **더 깔끔한 코드.** 프로젝트가 이미 강제하는 공개 기준을 지킵니다(DEC-108,
   `Docs/GDD/05_Refactoring_Standards.md`).

첫 출시는 **크로마 어워드 Season 2** 게임 부문 **퍼즐 & 전략** 카테고리 출품작입니다 **[사용자]**.
지켜야 할 규칙은 `Docs/GDD/references/CHROMA_AWARDS_S2.md`에 있고, 3장에 요약했습니다.
출품작은 Rust 버전이어야 합니다 **[사용자]**.

웹에서 업데이트하기 쉬워야 하고 **[사용자]**, 이후 Windows(Steam)와 Android(Play 스토어)에도
출시합니다 **[사용자]**.

## 3. 대회 제약 (REF-CHROMA-S2 기준)

네 항목이 같은 비중(각 1~10점)이며, 이 설계에서 각 항목에 대응하는 부분은 다음과 같습니다.

| 심사 기준 (각 25%) | 대응 |
|---|---|
| 주제·부문 목적 (게임플레이. 퍼즐 & 전략: 영리한 시스템, 명확한 규칙, 긴 튜토리얼 없음) | 플레이하며 시스템 하나씩 배우는 시나리오(5장) |
| 창의성·AI 활용 (독창적 세계, 장식이 아닌 의미 있는 AI) | 경제 시스템 자체, 제작 과정을 기록한 AI 아트·사운드(8장) |
| 완성도·기술 (버그 없음, 깔끔한 비주얼) | 픽셀 아트 UI, 성장 연출, 결과 일치 테스트와 릴리스 관문 |
| 사운드·감정 | 거래, 계약, 습격, 결과 화면에 맞춘 음악과 효과음 |

빌드가 반드시 지켜야 할 조건:
- 공개되고 임베드 가능한 웹 링크. 다운로드 없음. 소개한 그대로 동작.
- 게임 안의 모든 텍스트는 영어 (사용자와의 대화는 한국어지만 게임은 영어로 출시).
- AI 도구 최소 하나 사용 및 공개. 후원사 도구상은 도구 태그와 상당한 사용의 증거 필요.
- 다운로드 가능한 게임플레이 영상과 썸네일.
- 직접 만들었거나 라이선스가 있는 코드·아트·음악만. 타사 IP 금지.
- **제출하면 곧바로 1차 심사가 시작되고, 그때부터 수정 불가.**
- 게임이 갤러리의 iframe 안에서 실행될 수 있고, 그 안에서는 보통 교차 출처 격리(그리고 wasm
  멀티스레드)를 쓸 수 없음. **한 스레드만으로 턴 예산을 맞춰야 함** **[Claude]**. 스레드는 가능한 곳에서의 덤.

## 4. 검토한 방법

만드는 방법:

| 방법 | 장단점 | 결과 |
|---|---|---|
| **A. Rust 시뮬레이션 + 웹 UI(TypeScript, 지도는 Canvas), 데스크톱·모바일은 포장** | 시세표, 재무제표, 차트처럼 데이터가 많은 화면을 가장 빨리 다듬을 수 있음. wasm이 작음. UI는 Rust가 아니지만 무거운 계산은 전부 Rust | **선택 [사용자]** |
| B. Bevy: 전부 Rust | 언어·코드 하나. 표 위주 UI 도구가 약하고 웹 빌드가 크며 컴파일이 느리고 API가 자주 바뀜 | 제외: UI 시간과 완성도 |
| C. Macroquad + egui | 작고 빠름. egui가 개발 도구처럼 보여 완성도에 불리 | 제외: 완성도 |

A를 웹 밖으로 내는 방법 (코드가 막다른 길로 가지 않도록 지금 정함):

| 선택지 | 설명 | 결과 |
|---|---|---|
| Tauri 2 | 네이티브 Rust 코어(wasm보다 빠르고 스레드 사용), 작은 설치 파일, Steamworks 연동 가능. Android 지원은 데스크톱보다 덜 성숙 | **Windows/Steam [Claude, 사용자 수락]**, Android도 먼저 시도 |
| Capacitor | 성숙한 Android 포장. 코어는 wasm으로 실행 | Tauri 모바일이 막히면 **Android 대안** |
| PWA | 웹 빌드에 거의 공짜로 따라옴: 설치 가능, 오프라인, 즉시 업데이트 | **처음부터 포함 [Claude, 사용자 수락]** |
| Electron | 설치 파일이 크고 포장 도구 두 개를 관리해야 함 | 제외 |
| Dioxus | UI가 Rust라 A와 맞지 않음 | 제외 |

결과적으로 시뮬레이션 크레이트는 인터페이스 하나(7.2)를 세 방식으로 씁니다: 웹 워커 안의 wasm,
Tauri 안의 네이티브, 테스트 안의 네이티브.

## 5. 심사위원이 보게 될 게임

### 5.1 메인 메뉴 (위에서 아래 순서) [사용자]
1. 시나리오 1 "First Venture" (상행의 기본)
2. 시나리오 2 간접 투자 (주식과 채권)
3. 시나리오 3 라이선스와 국제 무역 (특수재)
4. 자유 모드. 맨 아래에 두어 시나리오를 먼저 따라가게 함

순서 외의 시나리오 제목은 임시입니다.

### 5.2 세 시나리오 공통 규칙 [사용자]
- 각각 약 30분.
- **고정 시드, 무작위 없음**: 정해진 이벤트만 일어나서 모든 플레이어가 같은 세계를 봄. 이는 고정 시드
  이상의 의미입니다(`DetRandom`이 이미 재현성을 보장함). 경제가 스스로 일으키는 무작위 사건과
  습격 판정을 시나리오에서는 **끄고**, 정해진 이벤트만 남깁니다. 이 스위치는 시나리오 전용 규칙입니다(5.7).
- **[Claude]** 시나리오는 출시용 전체 규모 세계(출시 `config.csv`, 상단 4,460개)에서 시나리오마다 정한
  시드로 돌립니다. 심사위원이 실제 경제를 보게 되고, 턴 예산도 그대로 적용됩니다.
- 각 시나리오는 **재무제표 형태의 결과 화면**(매출, 비용, 순이익)으로 끝나고 **순이익을 점수로** 보여 줌.
- 결과 화면에서 다음 시나리오로 가거나 메인 메뉴로 돌아감. **시나리오가 자유 모드로 이어지지는 않음.**
- **[Claude, 수락]** 시나리오 2와 3도 결정적인 순간(배당 입금, 특수재 해외 판매)에 시나리오 1과 같은
  성장 연출을 씀.

### 5.2a 턴이 넘어가는 방식 [사용자]
**"다음 주" 버튼을 눌러야만** 턴이 넘어갑니다. 문명 시리즈처럼 플레이어가 그 주의 행동(매매, 이동 명령,
계약, 투자)을 모두 마치고 버튼을 누르면 NPC가 움직입니다. 시나리오든 자유 모드든 시간이 저절로 흐르지
않습니다.

**[Claude]** 각 거래의 결과는 플레이어가 거래하는 순간 바로 보여 줍니다(5.6의 성장 연출도 턴 끝이 아니라
그때 재생). 명령 자체는 C#과 같이 턴의 명령 단계에서 적용합니다. 미리보기는 현재 상태에 그 주에 이미
쌓인 명령을 같은 순서로 더해 계산하므로, 턴이 실제로 적용하는 결과와 같습니다. 미리보기와 실제 결과가
같은지 테스트로 확인합니다. "다음 주"를 누른 뒤 턴을 계산하는 동안에는 화면에 NPC가 움직이는 모습을
보여 줍니다(계산은 워커에서 돌아감).

### 5.3 시나리오 1, 상행의 기본 [사용자]
1. 약 10분의 보호 구간: **처음 산 상품은 어디서 팔든 1.5배 값을 받음.**
   **[Claude, 수락]** 산 가격의 1.5배. 보호는 시간이 아니라 첫 판매로 끝남(심사위원마다 속도가 다르므로).
2. **공급 계약 의뢰**: 기한 안에 물건을 배송. 완료하면 소지금이 **시작 금액의 3배**가 됨. 공급 계약은
   NPC 사이에 이미 있으며(`Assets/_Game/Agents/Contracts.cs`), 이를 플레이어가 받는 의뢰로 넓힘.
3. **호위 용병 또는 보험**으로 상행을 지키며 위험과 비용을 저울질하는 법을 배움. 둘 다 이미 있음
   (`Docs/GDD/systems/SYS_ROUTE_HAZARDS.md`: 호위는 습격 확률 70% 감소, 보험은 화물 손실의 80% 환급).
   **[Claude, 수락]** 계약 경로에서 정해진 습격 한 번으로 대비했을 때와 안 했을 때의 차이를 보여 줌.

### 5.4 시나리오 2, 간접 투자 [사용자]
주식과 채권으로 기업에서 이익을 냄. 규칙은 이미 있음: 주식, 거래소, 공매도, 국채와 회사채(`SYS_BANKING`).
정해진 이벤트와 목표는 구현자에게 맡김(11장).

### 5.5 시나리오 3, 라이선스와 국제 무역 [사용자]
특수재는 라이선스가 있어야 팔 수 있고, 국가 간·대륙 간 무역에는 별도 라이선스가 필요함(DEC-116,
`SYS_LICENSES`). 이벤트와 목표는 구현자에게 맡김.

### 5.6 성장 연출 [사용자]
거래가 끝나면 **게임이 잠깐 멈추고, 소지금 창이 확대되며, 숫자가 실시간으로 올라감**. 성장이 눈에 보이게
하기 위함. **[Claude, 수락]** 동전 소리를 함께 재생.

### 5.7 시나리오 전용 규칙 [Claude, 수락]
1.5배 판매, 정해진 습격, 계약 의뢰 등 가르치기 위한 규칙은 **시나리오 모드에서만** 존재합니다. 이 규칙을
끄면 시뮬레이션은 C# 기준과 같은 골든 해시를 내야 합니다. 가르치려고 경제 자체의 동작을 흐리지 않기
위함입니다.

## 6. 정확성: C# 시뮬레이션과 결과 일치

**기준 [사용자]**: 다른 세션에서 진행 중인 작업(`meta-analysis-fixes`의 웹 빌드 테스트)이 끝난 시점의
C# 시뮬레이션 커밋. 그 커밋은 **`4bf3804`**(2026-11-04 기록, DEC-136)이며, 이 시점부터 C# 시뮬레이션 코드는 고정입니다. 규칙, 수치, 연산 순서를 그대로 옮기고, 도중에 발견한 버그는
이식에서 고치지 않고 보고합니다(DEC-108과 같음).

- 같은 수: 정수와 `Fx`(`i64` 안의 Q47.16), 대칭 반올림, 시뮬레이션 코드에 부동소수점 없음.
- 같은 난수: `DetRandom.For(seed, turn, stream, entity, salt)`와 `DetHash.Of`를 그대로 이식.
- **같은 저장 상태.** `GoldenRunTests`는 `SaveSerializer`가 쓰는 바이트를 해시합니다. Rust도 같은 형식을
  바이트 단위로 똑같이 쓰므로 골든 해시를 바로 비교할 수 있고, C# 세이브를 Rust에서 읽을 수 있습니다.
- 같은 턴 파이프라인: 단계, `(Order, Id)` 순서, 단계마다 이벤트 전달.
- **일치 범위 [Claude]**: 출시 설정이 쓰는 분기만 이식(`lod.mode,1`, 소문 끔, 출시 상인 설정).
  다른 분기를 덮으려고만 있는 골든 런(`GoldenRunTests`의 `Aggregate`, `Mixed`, `Rumors`, `PlainMerchants`)은
  이식하지 않음. LOD 집계는 어차피 실패 조건임. 관문은 나머지 모든 골든 런을 끝까지 맞추는 것.
- 어떤 시스템이 단계 끝까지 일치하지 않으면 그 시스템에 의존하는 시나리오가 기다림. 알려진 불일치가 있는
  빌드는 절대 출시하지 않음 **[Claude]**.
- 결과 일치 도구가 골든 시드와 설정으로 두 구현을 돌리고, 불일치가 나면 턴별·구성요소별로 상태를 비교해
  처음 어긋난 시스템을 찾음.
- 이식 순서는 모듈 의존 순서(`ModuleOrder`)를 따름. 각 시스템을 옮기자마자 C#과 대조한 뒤 다음으로 넘어감.

이식 중 C# 규칙 변경: 기준 커밋을 기록한 뒤부터 C# 코드는 고정 **[Claude]**. 새 규칙(시나리오 규칙)과
이후의 밸런스 작업은 Rust에서만 함.

## 7. 구조

### 7.1 저장소 구성 [Claude]
같은 저장소, Unity 프로젝트 옆에 둠(Unity는 `Assets` 밖의 폴더를 무시함):

```
engine/            Cargo 워크스페이스
  fes-core/        시뮬레이션: I/O 없음, 스레드 필수 아님, 플랫폼 코드 없음
  fes-data/        CSV 정의, 설정, 데이터 해시
  fes-save/        세이브 형식 (SaveSerializer와 바이트 호환)
  fes-wasm/        웹 워커용 wasm-bindgen 바인딩
  fes-parity/      C# 골든 결과와 대조하는 도구
web/               TypeScript UI (Vite), Canvas 지도 (PixiJS), PWA 매니페스트와 서비스 워커
.github/workflows/ CI와 배포
```

`Docs/GDD/`는 계속 설계 기록이고, 이 문서와 구현 계획은 `docs/superpowers/` 아래에 둡니다.

### 7.2 시뮬레이션 인터페이스
지금처럼(`GameSimulation.View` / `Actions`) UI는 시뮬레이션 상태를 직접 건드리지 않습니다.
- `step()`이 한 턴을 돌림. 명령은 턴 사이에 쌓임.
- 뷰는 UI로 넘길 수 있는 단순 복사본을 돌려줌(현재 시장, 소지금, 재무제표, 계약, 주식).
- 연출이 반응할 이벤트(거래 완료, 계약 완료, 습격, 배당)가 매 턴 함께 돌아옴.

웹에서는 시뮬레이션이 **Web Worker**에서 돌아서, 턴을 계산하는 동안에도 UI 애니메이션이 멈추지 않습니다.

### 7.3 성능
- 예산: 웹, 한 스레드, 전체 계산으로 한 턴 1초(DEC-110 규칙 그대로).
- 출발점: 개발 PC의 Chrome에서 Unity 웹 빌드, 전체 규모 세계, 출시 설정(상단 4,460개), 0~53턴,
  커밋 `c4470e2` 이후: 평균 1.03초, 최악 1.64초(새해), 54턴 중 19턴이 1초 초과. 상인 0.44~0.72초,
  가격 계산 0.39~0.49초, 분기 수요 예측 약 0.47초. 그 전 빌드는 목표를 맞췄으므로(평균 0.49초, 최악
  0.84초) `00_Architecture.md`는 낡은 상태. 이식을 시작할 때 이 출발점을 `Docs/GDD`에 기록.
- **관문 [Claude]**: 같은 세계와 턴, 개발 PC의 Chrome, itch.io 임베드 안에서 최악의 턴 1초 미만,
  **평균 0.7초 미만**(심사위원의 느린 PC를 위한 여유). 프로파일링은 마지막이 아니라 1단계에서 가격 계산과
  상인 이식부터 시작.
- 멀티스레드(wasm 스레드 위의 rayon)는 교차 출처 격리가 되는 곳에서만 쓰고 결과가 같아야 함. 예산은
  한 스레드 경로로 잼.
- Rust 빌드는 릴리스 최적화, LTO, `wasm-opt`를 씀. 구조를 바꾸기 전에 먼저 프로파일링.

### 7.4 코드 기준
C#의 한도(복잡도, 길이, 중첩, 매개변수, 파일 크기, 중복, 죽은 코드)를 Rust에 맞는 형태로 옮겨 CI에서
`clippy`(인지 복잡도, 줄 수, 인자 수를 같은 값으로)와 `rustfmt`로 강제. TypeScript는 ESLint로 같은 복잡도
한도 적용.

## 9. 배포

### 9.1 파이프라인 [사용자, 구조 확인]
- **매 push**: Rust 테스트, 결과 일치 검사, clippy, wasm 빌드, 웹 빌드, 개발 페이지에 배포.
- **릴리스**: 버전 태그. 같은 결과물을 `butler`로 itch.io에 버전 번호와 함께 올림. 결과 일치와 턴 예산을
  통과하지 못하면 릴리스가 막힘.
- **심사용 빌드**: 제출한 itch.io 페이지에는 검증된 릴리스만 올리고, **제출 뒤에는 갱신하지 않음**.
  개발은 별도 페이지에서 계속.
- **개인 웹사이트(나중)**: 같은 결과물을 버전별 경로(`/play/v1.2/`)에 올림. 잘못된 릴리스는 이전 경로를
  가리키게 해서 되돌림.

### 9.2 세이브
세이브는 6장의 바이트 호환 형식이고, 웹에서는 브라우저(IndexedDB)에 저장. 자유 모드는 저장하고,
시나리오는 매번 처음부터 시작 **[Claude]**. 현재 C# `FormatVersion`만 읽으면 되고, 옛 버전용
`ISaveMigration` 체인은 이식하지 않음(C# 세이브를 가진 플레이어가 없으므로) **[Claude]**.

## 10. 일정 (2026-12-24까지 약 7주)과 줄이는 순서

대략의 단계 [Claude], 구현 계획에서 구체화:
1. 핵심 타입, 데이터 로딩, 세이브 형식, 결과 일치 도구. 세계, 시장, 가격 계산 이식.
2. 나머지 시스템을 의존 순서대로 이식, 모든 골든 런이 일치할 때까지.
3. 웹 워커, UI 뼈대, 지도, 매매 화면. 시나리오 1 처음부터 끝까지.
4. 시나리오 2와 3, 결과 화면, 사운드와 아트 작업.
5. 웹 성능, 다듬기, 영상과 썸네일, 제출.

시간이 모자라면 이 순서로 줄임 **[사용자가 Claude 제안 수락]**:
1. Windows와 Android (이미 대회 이후로 미룸).
2. 자유 모드의 깊이 (심사는 시나리오로 함).
3. 시나리오 3개와 성장 연출은 끝까지 지킴.
